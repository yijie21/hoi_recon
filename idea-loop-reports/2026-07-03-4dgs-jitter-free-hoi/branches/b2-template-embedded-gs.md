# Template-embedded HOI Gaussians: MANO-rigged hand Gaussians + mesh-anchored object Gaussians optimized end-to-end through the rendering loss

**Branch ID:** `b2-template-embedded-gs`
**Overall score:** 4.5
**Verdict:** maybe (real but narrow mechanism-level delta — contact-factorized continuous-time parameterization — in a lineage BIGS/GHOST/GraG already occupy; one make-or-break ablation)

## Digest (card summary)

**TL;DR:** Optimize whole-clip hand and object trajectories - object wrist-locked during grasps, spline-smooth when free - through a rigged-Gaussian rendering loss, betting built-in coupling beats per-frame poses plus post-hoc filters.

**Why:**
- All four harness pipelines (HORT, ForeHOI, render-and-compare, do-as-i-do) jitter, float, err +33-43% in size
- Bet: make jitter unrepresentable - object pose := wrist pose composed with per-grasp transform G_k
- BIGS/GHOST/GraG all still keep per-frame poses; contact-factorized continuous-time state is unclaimed, window closing

**Pipeline:**
1. **Per-frame initialization** — Run HaWoR (hand+camera), SAM-3D canonical mesh, SAM2 masks, render_and_compare per-frame object poses. — `video -> per-frame MANO, camera, object SE(3), canonical mesh, masks`; reuses HaWoR, SAM-3D, SAM2, user's render_and_compare pipeline
2. **Contact segment detection** — Seed grasp/free segments from SAM2 mask adjacency plus hand-object proximity in init poses. — `masks + init poses -> grasp/free segment boundaries`
3. **Contact-factorized spline state** — Least-squares fit cumulative se(3) B-splines; during grasp k, object pose := wrist composed with G_k. — `per-frame poses + segments -> spline knots + per-grasp transforms G_k`; reuses Theseus/LieTorch spline implementations
4. **Template-rigged Gaussians** — Bind Gaussians to MANO faces (LBS, GART-style) and SAM-3D mesh faces; fit appearance, poses frozen. — `meshes + frames -> rigged hand/object Gaussian sets`; reuses GART rigging pattern, gsplat rasterizer
5. **Joint clip-wide optimization** — Optimize splines, G_k, scale, displacement field via photometric, silhouette, DINOv2, depth losses, coarse-to-fine. — `init state + video frames -> refined trajectories + mesh + appearance`; reuses render_and_compare loss/optimizer scaffolding
6. **Temporal-stability benchmark** — Score size/depth/ADD plus jitter, acceleration, scale-constancy, contact persistence versus baselines and baselines+SmoothNet/OneEuro. — `reconstructions -> accuracy + stability tables vs BIGS/GHOST + filtered baselines`; reuses user's HOI4D GT-depth harness (~20-30 clips)

**What's new:** Get a Grip (ECCV'24) locks object-to-hand only for CAD templates in annotated grasp segments; here contact-factorized se(3) splines cover whole clips of unknown SAM-3D objects inside rendered Gaussians.

**Top risks:**
- ⚠ Wrist-locking imports HaWoR tracking error into object pose; escape hatches reintroduce per-frame DOF
- ⚠ Jitter lives in photometric null space (occlusion, texturelessness); central filter-ablation may come out flat
- ⚠ Crowded lineage (BIGS, GHOST, GraG, CARI4D); assembly-level delta risks borderline-reject

**Kill test:** One-week pilot, 2-3 HOI4D clips: full spline+G_k optimization versus per-frame render_and_compare plus SmoothNet, both given GT depth. Go if ADD/depth accuracy AND stability clearly improve; if margin is flat, pivot to benchmark-only paper.

**If it works:** First HOI method where grasp rigidity and smoothness are structural; beats BIGS/GHOST and filtered baselines on accuracy plus new temporal-stability metrics (CVPR).

## Branch definition

- **Angle:** Analysis-by-synthesis where the ONLY free variables are MANO pose/shape/global trajectory, object 6-DoF trajectory, and Gaussian appearance attached to the templates — a GART/GaussianAvatar-style rig extended to two interacting entities with unknown object geometry (Gaussians initialized on the SAM-3D mesh, optionally refining it). - **Core Hypothesis:** Backpropagating a multi-frame differentiable-splatting photometric loss into low-dimensional template parameters is a fundamentally stronger temporal coupling than any post-hoc filter or per-frame render-and-compare: jitter cannot exist unless it improves photometric fit in every frame, so the solution is stable by construction while pixel-accurate.
- **Why Distinct:** Templates are the parameterization inside the GS loop (low-DOF, semantically constrained), versus b1 where GS is free-form and templates come after. This is the direct 'GaussianAvatar-for-HOI' framing and the branch whose novelty hinges most on whether hand-avatar-GS papers already cover interaction with unknown objects.

  - GART / GaussianAvatar / 3D Gaussian hand avatars

  - SAM-3D
  - user's render_and_compare framework (loss/optimizer scaffolding)

## Clarification

- **Problem Statement:** Given a monocular (optionally egocentric, moving-camera) RGB(-D) video of a hand manipulating an unknown rigid object, recover a metric, world-frame, temporally consistent 4D reconstruction — MANO shape + pose trajectory, object geometry, and object SE(3) trajectory — under an offline per-clip compute budget. Every existing pipeline, whether feed-forward (HORT, ForeHOI), render-and-compare, diffusion-guided (do-as-i-do), or Gaussian-splatting-based (BIGS CVPR'25, GHOST'26, Grasp-in-Gaussians'26), ultimately keeps PER-FRAME pose variables that are at best weakly coupled by smoothness losses or post-hoc filters; empirically (our HOI4D GT-depth harness) this yields object size errors of +33–43%, absolute depth errors of −29% to −81% for monocular methods, and frame-to-frame jitter/floating of the grasped object in all four tested pipelines — artifacts a filter cannot fix because it never sees pixels. The problem: re-spend the already-accepted multi-hour budget on ONE joint spatio-temporal optimization in which temporal coherence and hand-object attachment are structural properties of the parameterization, while matching or beating per-frame accuracy on metric world-frame benchmarks.
- **Technical Core:** Analysis-by-synthesis over the WHOLE clip where the only geometric unknowns are low-DoF template trajectories, and time-invariant Gaussian appearance rigged to the templates turns texture into a self-supervised tracker (any jitter misaligns the shared texture in every frame and raises the loss). (1) STATE: hand = shared MANO beta + per-joint rotation trajectories as cumulative B-splines (knots at 4–8 Hz) + wrist se(3) spline; N_h Gaussians bound to MANO faces (barycentric anchor + normal offset, LBS-skinned, GART-style pose-corrective blendshapes). Object = canonical SAM-3D mesh (from the best-visibility frame; global scale is a free variable) with face-anchored Gaussians (bounded local offsets) + optional per-vertex displacement field with Laplacian/ARAP regularization to correct SAM-3D's aspect-ratio bias (measured −21% on our kettle clip). (2) CONTACT-FACTORIZED OBJECT TRAJECTORY — the key mechanism: contact segments are seeded from SAM2 mask adjacency + init proximity; during a held segment k, T_obj(t) := T_wrist(t) ∘ G_k with a SINGLE latent grasp transform G_k per segment plus a heavily-regularized slow drift spline for in-hand adjustment; during free segments T_obj(t) is a cumulative se(3) B-spline (continuous-time-SLAM parameterization imported into HOI); segment boundaries get optimizable soft blending. Hand-relative jitter and 'floating' are thus impossible by construction during grasp — not penalized, unrepresentable. (3) LOSSES, summed over frame minibatches spanning the clip: composited depth-sorted rasterization of both Gaussian sets → masked L1 + D-SSIM photometric with per-frame affine exposure; per-entity silhouette vs SAM2 alpha; DINOv2 feature-metric loss for specular/textureless robustness; depth term (GT depth on HOI4D, metric-mono depth in the wild) resolving absolute scale/depth; robust low-weight 2D keypoint anchor (Geman-McClure so per-frame detector jitter is not re-imported); SDF penetration hinge + fingertip attraction during held phases; small acceleration penalties on spline knots. (4) SCHEDULE (~1–4 GPU-h per clip, i.e. do-as-i-do's budget): Stage A — init from HaWoR (world hand + camera) and the existing render_and_compare framework (per-frame object poses via its mask/depth losses), least-squares spline fit, freeze poses, fit appearance; Stage B — joint optimization of splines + grasp transforms + scale, coarse-to-fine in image resolution and knot density (2→8 Hz); Stage C — unlock displacement field and a bounded per-frame residual (±1σ around the spline) to recover true high-frequency motion, reported with/without. (5) EVALUATION on the extended HOI4D GT-depth harness (~20–30 clips): metric size/depth error, world MPJPE, chamfer/ADD vs GT-depth-unprojected reference, plus NEW temporal metrics — acceleration error (mm/s²), pose jitter (deg/frame², mm/frame²), apparent-scale constancy, contact persistence — against the 4 harness pipelines, BIGS, GHOST, and critically against each baseline + OneEuro/SmoothNet/spline post-filtering, the ablation that proves joint pixel-level optimization strictly dominates filtering (filters trade jitter for lag and cannot correct scale/depth/floating).
- **Novelty Claim:** To our knowledge the first HOI reconstruction in which both interacting entities' motions are optimized as contact-factorized continuous-time trajectories (object pose expressed relative to the hand through a per-grasp latent transform, se(3) splines when free) inside a jointly-rendered template-rigged Gaussian-splatting objective — making temporal smoothness and grasp rigidity properties of the parameterization rather than of losses or filters, unlike BIGS/GHOST/Grasp-in-Gaussians which all retain per-frame pose variables — and the first to benchmark GS-based HOI on metric world-frame temporal-stability metrics (jitter, scale constancy, contact persistence) with a GT-depth harness.
- **Target Venue:** CVPR (primary; BIGS/GHOST lineage venue — a systems+evaluation 3D reconstruction paper fits CVPR better than ICLR/CoRL; ICCV/3DV as fallback)
- **Key Assumptions:**
  - Object is rigid: SE(3) trajectory + small displacement-field refinement suffices; articulated/deformable objects are out of scope (stated limitation, future work).
  - SAM-3D produces a topologically usable canonical mesh from at least one high-visibility frame, with errors correctable by the displacement field + silhouette losses (harness evidence: kettle mesh usable but −21% size / aspect-ratio bias).
  - Per-frame initializations (HaWoR hand+camera, render_and_compare object poses) land within the photometric basin of convergence (~15° / ~3 cm); coarse-to-fine rendering and the DINOv2 feature-metric loss are assumed to widen this basin enough on real clips.
  - SAM2 video segmentation with point prompts is reliable per entity (the harness already showed text prompts fail with distractor objects and point+negative prompts fix it), and mask adjacency is a good enough seed for contact-segment detection.
  - Camera intrinsics and extrinsics are available (HOI4D GT; SLAM/HaWoR in the wild) — world-frame smoothness and metric claims degrade with camera-pose error; optional camera-refinement spline mitigates but does not remove this dependency.
  - Absolute metric scale/depth requires SOME depth signal (HOI4D GT depth for the benchmark, metric monocular depth in the wild) or the hand-size prior; RGB-only operation works but with weaker metric claims.
  - Object appearance is approximately time-invariant over a clip (per-frame affine exposure absorbs lighting drift); heavy motion blur and strong specularity are handled by loss downweighting, not modeled.
  - Grasp rigidity holds within detected contact segments up to slow drift (regrasping/rolling manipulation is captured by segment splitting + the drift spline; rapid dexterous regrasps may violate this).
  - Offline budget of ~1–4 GPU-hours per clip is acceptable (matches the already-spent do-as-i-do budget); this is not a real-time method and does not claim to be.
  - Enough per-entity visual signal (texture, silhouette motion, or depth) exists to disambiguate pose; textureless rotationally-symmetric objects fall back on silhouette+depth+contact terms with expectedly weaker rotation accuracy (report symmetry-aware metrics).
  - HOI4D provides sufficient clips with GT depth + object annotations across categories (~20–30 clips) to make the extended harness statistically meaningful, and BIGS/GHOST code runs on it for direct comparison (both repos are public).

## Pressure test

- **Failure Modes:**
  - Core hypothesis can backfire empirically: T_obj(t) := T_wrist(t) ∘ G_k hard-wires HaWoR wrist-tracking error (jitter, drift, depth bias — worst exactly when the hand is occluded by the grasped object) directly into the object trajectory. If mask/depth-based object evidence is locally better than wrist tracking, the factorization DEGRADES object accuracy versus per-frame baselines, and the headline 'parameterization dominates losses' claim collapses. The escape hatches (drift spline, soft segment blending, Stage-C bounded per-frame residuals) each reintroduce the per-frame DOF the pitch says are unrepresentable — a sharp reviewer will call the final system 'per-frame poses with a strong spline prior', i.e., exactly the loss/filter coupling the paper attacks.
  - The photometric-tracker premise is weakest where jitter is worst: during manipulation the object is 50–80% hand-occluded, hands are near-textureless and self-similar, objects are often specular or rotationally symmetric, and typical per-frame jitter (1–3 mm / 1–2°) is sub-pixel at HOI4D viewing distances. In these null spaces of the rendering loss the parameterization suppresses jitter by PRIOR, not by pixel evidence — philosophically the same as a filter — so the central ablation (joint pixel optimization vs baseline+SmoothNet/spline post-fit) may show a small or zero accuracy delta, leaving only smoothness gains that a spline post-fit also achieves. The whole paper stands or falls on this one ablation and it has a realistic chance of coming out flat.
  - Contact-segmentation cascade: SAM2 mask adjacency + proximity is a weak grasp detector (hovering ≠ grasping; occlusion merges masks; regrasps split poorly). A wrong contact segment imposes rigid attachment on a free object (or vice versa), producing large correlated errors — a strictly worse failure mode than the baselines' independent per-frame noise, and one reviewers will probe with regrasp/handover clips.
  - Novelty is assembly-level and the field is closing fast: BIGS (CVPR'25) owns rigged-GS-for-HOI, Get a Grip (ECCV'24) owns hand-relative grasp factorization, SplineGS/HOIGS own splines-in-GS, GraG already markets jitter suppression, and CARI4D (CVPR'26, NVIDIA) claims category-agnostic METRIC-SCALE temporally consistent 4D HOI via render-and-compare + contact reasoning. The remaining delta — composing these inside one GS objective — reads as 'known ingredients, new glue' unless gains are large; that is the canonical CVPR borderline-reject profile.
  - The evaluation-protocol contribution is also eroding: acceleration-error metrics (Acc-h/Acc-o vs GT) already appear in 2026 4D-HOI papers (e.g., THO spatial-temporal transformer lineage, CARI4D), and accel error has been standard in human motion since VIBE. 'First temporal-stability benchmark for GS-based HOI with GT depth' survives, but that is a thin qualifier, not a headline claim.
  - Temporal metrics are gameable by construction and reviewers know it: a spline parameterization trivially wins jitter/accel/scale-constancy while risking lag and oversmoothing of true fast motion (regrasps, impacts). Worse, measuring mm/s² acceleration error requires per-frame GT object pose far more accurate than HOI4D's (partly interpolated, annotator-noisy) annotations provide — the evaluation may be measuring GT noise. Mocap-grade alternatives (ARCTIC, DexYCB, HO3D) have templates and template-based SOTA that would beat a SAM-3D-mesh method on raw accuracy, an unflattering comparison the paper cannot avoid being asked for.
  - Baseline reproduction risk: GHOST and GraG are preprints with unverified code availability; BIGS was evaluated under a different protocol. If these cannot be run fairly on the HOI4D GT-depth harness in world-frame metric terms, the comparison table degrades to the user's own 4 pipelines plus filters, weakening the SOTA claim.
  - Headline motivation numbers are vulnerable: the −29% to −81% depth and +33–43% size errors quoted for baselines come from methods NOT given the depth signal this method uses. The mandatory fairness ablation (baseline + same depth term + global scale correction + post-filter) may close most of the motivating gap before the proposed machinery even enters.
  - Scooping window: submission would target CVPR 2027 (Nov 2026 deadline); given 4+ GS-HOI entries in the 2026 preprint wave alone, the probability that a contact-factorized or continuous-time HOI-GS paper appears before then is substantial, and the branch has no second line of defense if the parameterization claim is taken.
- **Unsound Assumptions:**
  - 'Jitter cannot exist unless it improves photometric fit in every frame' — false as stated: jitter lives in the photometric null space (occluded, textureless, symmetric, motion-blurred regions), which is precisely where per-frame methods jitter most; there the parameterization acts as a prior indistinguishable in kind from a filter.
  - Basin-of-convergence assumption (~15°/~3 cm from per-frame init) is contradicted by the branch's OWN harness evidence of −29% to −81% absolute depth error and +33–43% size error in the initializing pipelines; coarse-to-fine + DINOv2 widening the basin that far is asserted, not evidenced.
  - Grasp rigidity within mask-adjacency-detected segments: adjacency is not contact, and in-hand rotation/rolling manipulation (common in HOI4D categories like scissors, kettle pouring) violates the single-G_k-plus-slow-drift model in ways soft blending only papers over.
  - Time-invariant object appearance with per-frame GLOBAL affine exposure: the hand casts strong spatially-varying moving shadows and inter-reflections on the object during manipulation; a global affine cannot absorb this, injecting structured photometric error exactly at the contact region the method cares most about.
  - HOI4D GT object-pose annotations are accurate and temporally dense enough to score acceleration error in mm/s² — unverified and likely false for second-derivative metrics.
  - BIGS/GHOST/GraG code runs on HOI4D for direct world-frame metric comparison — GHOST and GraG are preprints; code release and protocol compatibility are unverified.
  - That matching do-as-i-do's 1–4 GPU-h budget is acceptable to reviewers when CARI4D and feed-forward competitors (THO at 31.5 FPS) are simultaneously claiming comparable temporal consistency at orders-of-magnitude lower cost — 'offline is fine' is a 2024 assumption applied to a 2027 reviewing climate.
- **Feasibility:**
  - **Data:** MODERATE. HOI4D with GT depth exists and the team's harness already runs on it, but ~20–30 clips is a small benchmark for cross-category claims, GT pose annotation quality is likely insufficient for second-derivative (acceleration) metrics, and the mocap-grade alternatives (ARCTIC/DexYCB/HO3D) come with object templates that both undercut the 'unknown object' story and invite unflattering comparison to template-based SOTA. In-the-wild results will be qualitative only.
  - **Compute:** GOOD. 1–4 GPU-h/clip × ~30 clips × (method + ~6 ablations + 7–9 baselines/filter variants) ≈ 500–1500 GPU-h — comfortably within a rented multi-GPU budget over 2–3 months. The differentiable pipeline (two rigged Gaussian sets, spline chain rule, segment blending) is heavy engineering but all components have public reference implementations (GART, gsplat, Theseus/LieTorch splines).
  - **Evaluation:** MEDIUM-RISK, and it is where the paper lives or dies. Strengths: the harness exists, and the proposed filter-ablation (baseline + OneEuro/SmoothNet/spline post-fit) is the right experiment. Risks: (1) that very ablation may show the parameterization adds little over spline post-fitting on accuracy, since temporal metrics favor splines by construction; (2) fairness demands giving baselines the same depth signal, which may erase the motivating scale/depth gaps; (3) GHOST/GraG reproduction is unverified; (4) accel-error metrics are already appearing in 2026 4D-HOI papers, so the protocol is not cleanly first. A 2–3 clip pilot of the full Stage A→C loop versus per-frame+SmoothNet is cheap (~1 week) and would settle the make-or-break question before committing.
