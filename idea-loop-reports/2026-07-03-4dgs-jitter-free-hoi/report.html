Use 4D Gaussian Splatting (4DGS / dynamic 3DGS) as the representation or temporal-consistency backbone for stable, jitter-free 4D hand-object interaction (HOI) reconstruction from video.

Motivating observation (from our own experiments): We ran 4 HOI reconstruction methods on real videos (wild clips + a HOI4D egocentric kettle clip with GT RGB-D) — (1) render_and_compare, the user's own CHOIR-spine per-clip optimization method (MANO hand + model-free object mesh + 6-DoF trajectory + contact); (2) do-as-i-do, a 7-stage pipeline (SAM3 segmentation → SAM-3D object mesh → MoGe/GT pointmaps → HaWoR hands → GeoCalib gravity → TAPIR velocity → guided-diffusion object tracking, ~8.5h/clip); (3) ForeHOI (feed-forward, DepthAnything3 + FoundationPose); (4) HORT (feed-forward point cloud).

ALL of them produce temporally jittery / floating hands and objects. Diagnosed root causes: per-frame monocular estimators are independently noisy — HaWoR hand-depth wobble (frame-to-frame depth correlation 0.775, wiggle ratio 7.9), per-frame depth/scale inconsistency, per-frame pose regression with no temporal coupling. Temporal smoothing (median/average filters on trajectories) was only a band-aid.

Even with GT depth injected (HOI4D), and even with hours of per-clip optimization or guided diffusion, jitter persists because errors are optimized per-frame or with weak temporal priors.

The user's insight: with the SAME multi-hour per-clip compute budget, a high-quality 4D Gaussian Splatting reconstruction of the dynamic scene can be built that is temporally smooth and stable (photometric consistency across ALL frames jointly enforces temporal coherence). So: can 4DGS be used as the foundation for HOI reconstruction that is stable by construction?

Candidate framings to branch on (non-exhaustive, please expand): (a) reconstruct dynamic scene as 4DGS first, then fit/extract MANO hand + rigid object 6-DoF from the coherent Gaussian trajectories (GS as a temporal denoiser/scaffold); (b) template-embedded Gaussians — attach Gaussians to MANO mesh + object mesh and optimize pose/shape parameters directly through GS rendering loss (analysis-by-synthesis with photometric supervision across all frames jointly, like GaussianAvatar/GART-style but for HOI); (c) hybrid: rigid-object Gaussians constrained to SE(3) trajectory + articulated hand Gaussians rigged to MANO, plus contact constraints between them; (d) use 4DGS as pseudo-ground-truth generator / distillation target for training feed-forward HOI models.

Setting constraints: monocular RGB video (egocentric like HOI4D or third-person wild clips), model-free/unknown objects preferred (SAM-3D or GS-native object shape), RGB-D optionally available (HOI4D GT depth). Per-clip optimization time budget of several hours is ACCEPTABLE (already paying it). Hardware: 2× RTX 4090 48GB.

The user's existing assets: working MANO fitting (HaWoR), object segmentation (SAM3), object mesh gen (SAM-3D), metric depth (MoGe/DA3-metric), point tracking (TAPIR), the render_and_compare optimization framework, and the HOI4D GT-depth eval harness we just built (kettle clip, depth/size/contact metrics).

Novelty check should cover (2023–2026): existing Gaussian-splatting hand/object works — e.g. hand avatar GS (GaussianHand, 3D Gaussian hand avatars, GART, GaussianAvatar), HOI-specific GS (any "GaussianHOI"-type papers, MANUS grasp capture, hold/HOLD-style neural implicit HOI, BundleSDF, Dyn-HaMR temporal hand), dynamic scene GS (4DGS, Deformable-3DGS, Dynamic 3DGS tracking by persistent Gaussians, Shape-of-Motion, MoSca, SplaTAM), and whether anyone has done contact-aware template-embedded GS for monocular in-the-wild HOI with unknown objects.

Key question: is the gap real — stable temporally-coherent 4D HOI from monocular video via GS-based joint optimization — and what is the minimal doable pipeline that beats our current 4 baselines on stability (jitter metrics) while keeping accuracy (we have the HOI4D GT harness to prove it)?

Full analysis — problem, technical core, all closest works, complete pressure test

Angle

Minimal-intervention framing targeting the diagnosed root cause (per-frame depth/scale inconsistency and hand-depth wobble): use static-scene Gaussians + GS-SLAM-style joint camera/scale optimization (SplaTAM/MoGe-anchored) to produce a temporally consistent metric depth + camera trajectory, then re-run the UNCHANGED existing HOI methods on top of the stabilized depth/scale. No hand or object Gaussians at all.

Core hypothesis

A large fraction of the observed jitter is scale/depth wobble, not pose error; fixing the shared scale/camera/depth substrate via multi-frame GS consistency eliminates it upstream, and this can be quantified precisely with the HOI4D GT-depth ablation (GT depth injection already showed residual jitter, so this branch also stress-tests whether the root-cause diagnosis is complete).

Why distinct from the other branches

It changes the INPUT to HOI methods rather than the HOI representation or optimizer — cheapest, most falsifiable branch, and doubles as the ablation that tells you how much of b1-b3's gain comes from scale stabilization versus pose coupling. Also the only branch that remains useful if template-embedded GS turns out to be crowded prior art.

Problem statement

Monocular 4D hand-object-interaction pipelines of every family — per-frame feed-forward (HORT), video feed-forward (ForeHOI), optimization-based (render_and_compare/CHOIR), and tracker-based (do-as-i-do) — produce temporally unstable metric reconstructions.

On a common harness the failures are measured, not anecdotal: HORT's hand centroid teleports ~1.15 m in z frame-to-frame while x/y barely move; do-as-i-do's per-frame depth gauge swings 2x (translation_scale 0.52->1.01), producing 1.75x apparent-size flicker whose source is the HaWoR hand anchor (corr 0.775), and the hand's own depth wobbles 7.9x its true path length; render_and_compare's hand comes out at a uniform 0.77x scale; absolute object depth/size errors on HOI4D reach 29-81%.

Yet injecting GT sensor depth into the same UNCHANGED pipelines makes object depth/size essentially exact (0% error for render_and_compare; 0% depth for do-as-i-do with a depth anchor), and swapping a better per-frame depth net (MoGe->DA3-metric) changes nothing (1.75x->1.76x flicker).

The shared root cause is therefore not pose estimation but the per-frame, independently estimated metric gauge (depth scale/shift, camera pose, global scale).

The problem: from the monocular video alone, recover the temporally consistent metric substrate — camera trajectory, one global scale, per-frame gauge-corrected dense depth with amodal background completion — that the oracle experiment shows is the missing input; feed it to the four existing HOI pipelines unchanged; and quantify precisely what fraction of the GT-depth oracle's stability and accuracy gains this substrate restores, thereby decomposing 4D HOI jitter into gauge error vs. pose error vs. shape-prior error.

Technical core

One mechanism — per-frame monocular depth-gauge re-anchoring against a static-scene 3D Gaussian bundle adjustment — wrapped in a 4-part system.

(1) Dynamic-masked static-scene 3DGS BA (offline, all frames jointly; not incremental SLAM): reuse the SAM2/SAM3 hand+object masks every baseline already computes to exclude dynamic pixels; jointly optimize {background Gaussians G; per-frame camera T_t in SE(3); one global metric scale s; per-frame 2-parameter affine depth-gauge corrections (a_t, b_t) on the monocular metric-depth prior (MoGe-2/DA3-metric)} under an opacity/silhouette-gated photometric loss on background pixels + lambda*|D_GS,t - (a_t*D_mono,t + b_t)| on co-visible static pixels + GeoCalib gravity alignment + shrinkage of (a_t,b_t) to (1,0) + camera-trajectory smoothness.

A single static model explaining all frames makes background depth consistent BY CONSTRUCTION; s is pinned by robust cross-frame consensus of the metric prior over static pixels, optionally sharpened by object-at-rest support-plane contact. Static-camera clips degrade gracefully to multi-frame depth consensus.

(2) Gauge transfer to dynamic pixels: apply the background-fitted correction D~_t = a_t*D_mono,t + b_t to ALL pixels, including the hand/object regions the Gaussians never model — valid exactly because every diagnosed failure is a per-frame GLOBAL gauge error (uniform 0.77x hand scale; 2x scale swing; z-only teleports), not a local relative-structure error; the GS additionally renders amodal support-surface depth behind the dynamic masks plus per-pixel reliability from opacity/residuals.

(3) Injection through the interface the HOI4D GT-depth harness already defines (16-bit metric depth + K at real_perception.py's sensor-depth path): render_and_compare consumes D~_t in place of MoGe (the path proven exact under GT injection); do-as-i-do switches its object anchor from the HaWoR hand to the substrate pointmap via its existing --gt-anchor code path, then transfers the object's stabilized depth back to the hand with the grasp-preserving common-delta rule — inverting the current hand->object error flow; HORT and ForeHOI keep their networks and get a closed-form per-frame re-gauge (per-frame translation + one global scale aligning their predicted points to D~_t inside their own masks).

(4) Oracle-sandwich evaluation: every method x {monocular, +substrate, +GT-depth} on HOI4D GT align_depth, reporting accuracy (object size/depth/center error, hand MPJPE) and a stability suite (apparent-size flicker, depth wiggle ratio = z-path/net-displacement, acceleration jitter, grasp consistency), against substrate ablations (per-frame depth + temporal filtering, consistent-video-depth/pose engines like ViPE or Video-Depth-Anything, COLMAP+MVS) to isolate what GS BA specifically adds (joint camera+scale, amodal support depth, uncertainty).

Headline number: fraction of the oracle gap closed with zero changes to the HOI methods.

Key assumptions

  • Gauge dominance transfers: monocular metric-depth error on dynamic hand/object pixels shares the per-frame global affine gauge of the static background, so background-fitted (a_t,b_t) corrects dynamic pixels too — directly verifiable per-pixel on HOI4D GT depth BEFORE building the system; fails if depth nets have region/category-dependent bias exceeding the gauge term.
  • Enough static, textured background is co-visible across frames (true for table-top/egocentric HOI like HOI4D and wild6) and hand+object masks do not dominate the frame; enough camera parallax for BA — a static camera degrades gracefully to multi-frame depth consensus, which already fixes gauge wobble.
  • The injection interface reaches each pipeline where it matters: proven for render_and_compare and do-as-i-do by the GT-depth harness (0% depth error, existing sensor-depth and --gt-anchor code paths); assumes output-side per-frame re-gauging of HORT/ForeHOI (no network changes) still counts as 'unchanged' and captures most of their placement error.
  • A single global metric scale exists and is recoverable (rigid background, constant pinhole intrinsics after GeoCalib); if the metric depth prior is globally biased, the substrate is consistent-but-uniformly-mis-scaled — stability gains persist but absolute accuracy is bounded by that bias unless object-at-rest support contact pins the scale.
  • Residual error under the GT-depth oracle (HaWoR hand-depth wobble; SAM-3D canonical-shape -21% size residual) is separable from gauge error and partly addressable by the object->hand anchor flip / grasp-preserving delta without touching MANO pose; if most jitter had survived the oracle, the causal claim inverts and the paper degrades to an analysis-only result.
  • Novelty survives the crowded-GS field: template-embedded HOI Gaussians (e.g. Interaction-Aware 4DGS, ICLR'26 submission) reconstruct hand+object WITH Gaussians, whereas this branch deliberately has none and contributes the substrate + causal decomposition; generic pose/depth engines (ViPE, Video-Depth-Anything, robust CVD) must be included as substrate baselines and matched/beaten for the GS-BA choice to be justified — otherwise the contribution reduces to the diagnosis + injection protocol, which remains the paper's core.
  • Compute fits the accepted budget: GS BA at roughly 10-40 min per 5s clip on one GPU is small against the ~3-8 h already spent per clip (do-as-i-do guided-diffusion tracker), making 'spend the per-clip budget on the substrate' credible.
  • Stability metrics (apparent-size flicker, wiggle ratio, acceleration jitter, grasp consistency) formalized from the repo's diagnostics will be accepted by reviewers as meaningful alongside standard accuracy metrics — they double as a contribution (a 4D-HOI stability protocol) but are not yet community-standard.

Novelty moderate not pre-empted search: verified-by-search

The surrounding rings are crowded and fast-moving: world-grounded HOI reconstruction saw WHOLE, AGILE, CHOIR, and Zero-shot In-Scene Manipulation all appear within roughly the last 8 months, and consistent metric depth/pose engines (MegaSaM, ViPE, Video Depth Anything) plus dynamic-masked static GS (DAS3R) are mature commodity infrastructure.

But the exact niche — an oracle-controlled causal decomposition of HOI jitter into gauge vs pose vs shape error, fixed upstream and fed to unchanged existing pipelines — is empty; no analysis-style paper of this kind exists for hand-object reconstruction.

Sparse niche inside a crowded neighborhood nets out to moderate, with the main erosion vector being that WHOLE-style world-grounded HOI systems could absorb the framing within one review cycle.

Full novelty delta

Every mechanism component exists separately — dynamic-masked SLAM/BA with background-derived metric scale (TRAM, HaWoR), static-scene 3DGS from dynamic video (DAS3R), metric camera+depth engines (MegaSaM, ViPE), per-frame affine depth alignment (standard in CVD work) — but no published work (1) recovers the full metric substrate (camera trajectory + one global scale + per-frame affine gauge corrections + amodal support depth) via static-scene GS bundle adjustment and transfers the background-fitted gauge to dynamic hand/object pixels, (2) injects it into FOUR unchanged SOTA HOI pipelines through their existing depth/anchor interfaces, or (3) runs the oracle-sandwich (monocular / +substrate / +GT-depth) causal decomposition showing gauge wobble — not pose error — dominates 4D HOI jitter, with a formalized stability protocol (apparent-size flicker, wiggle ratio, grasp consistency).

The novelty therefore lives in the HOI-domain causal diagnosis + injection protocol + decomposition benchmark, not in the GS BA machinery itself.

The load-bearing risk is exactly the one the branch names: if off-the-shelf ViPE or MegaSaM depth+pose fed through the same interfaces closes a similar fraction of the oracle gap, the paper's system contribution reduces to the analysis — still publishable as a CVPR analysis paper, but with a weaker method claim, so the GS-vs-ViPE ablation is make-or-break and should be run first.

⚠ Failure modes

  • MAKE-OR-BREAK BASELINE KILLS THE METHOD: ViPE / MegaSaM / Video-Depth-Anything already output temporally consistent metric depth + camera poses from dynamic monocular video. If feeding any of them through the same injection interface closes a similar fraction of the oracle gap (likely, since the substrate spec is exactly what they produce), the GS-BA machinery is dead weight and the paper collapses to 'we plugged an existing depth engine into existing pipelines' — an analysis paper with borderline-reject odds at CVPR. The branch names this risk itself but currently has zero evidence GS-BA wins.
  • GAUGE-TRANSFER EXTRAPOLATION FAILURE: the affine correction (a_t, b_t) is fitted only on static background pixels — in tabletop/egocentric HOI that is mostly a near-planar desk at a narrow depth range, making the 2-parameter regression ill-conditioned (a and b nearly collinear); applying it to near-field hand/object pixels is extrapolation outside the fitted depth range, and monocular depth nets have depth- and category-dependent bias (hands/skin are a known failure category). If the per-pixel verification pilot on HOI4D GT depth fails, the paper's one mechanism dies. This should be experiment #1, before any GS code is written.
  • TRIVIALITY ATTACK: the GT-depth oracle already proves 'better depth in → better output'; reviewers can argue the delta contribution is just monocular-video depth-estimation quality, which belongs to the video-depth literature, and the HOI part is plumbing. The causal gauge-vs-pose decomposition is the real novelty, but decomposition-only papers need breadth the current evidence lacks.
  • EVIDENCE BASE IS n=1: the entire root-cause diagnosis (0% error under GT depth, hand-anchor corr 0.775, 2x scale swing) comes from one kettle clip in compare/hoi4d/depth_eval.md. The oracle residuals already visible there (do-as-i-do -21% size from SAM-3D canonical shape; HaWoR hand-depth wobble surviving GT depth) mean the substrate ceiling is below 'fixed', and on other object categories the gauge fraction could be much smaller — the headline 'gauge dominates' claim could invert on a broader clip set.
  • 'UNCHANGED PIPELINES' FRAMING ERODES: 2 of 4 pipelines are not actually unchanged — HORT/ForeHOI need output-side per-frame re-gauging (post-hoc alignment, itself arguably a trivial baseline), and do-as-i-do needs the anchor flip + grasp-preserving delta rule (a real pipeline modification, already implemented as --gt-anchor). A careful reviewer will call the headline framing oversold, and two of the four 'SOTA baselines' (render_and_compare, do-as-i-do) are internal/reproduction stacks, not published SOTA.
  • EVAL MATRIX VS COMPUTE: 4 methods x (monocular / +substrate / +GT) x substrate ablations (ViPE, VDA, COLMAP+MVS, temporal filtering) x enough clips to be credible (>=20-50) explodes; do-as-i-do alone at ~3h per 5s clip means ~360+ GPU-hours for a 20-clip x 6-condition slice of one method on a single-GPU box. Pruning is possible but reviewers will notice do-as-i-do evaluated on 5 clips.
  • STABILITY METRICS + SMOOTHING BASELINE: the flicker/wiggle/grasp-consistency suite is homegrown; naive temporal smoothing of per-frame outputs can match the stability numbers cheaply, so differentiation must come from absolute accuracy — which is bounded by the metric prior's global bias unless the fragile support-plane-contact heuristic works. If MoGe-2/DA3 is globally biased on a scene, the substrate is consistent-but-wrong and accuracy gains vanish.
  • STATIC-SCENE GS BA FRAGILITY IN HOI: mask leakage is real (their own eval documents SAM3 locking onto the wrong kettle), the manipulated object transitions static->dynamic mid-clip, hands+object can dominate egocentric frames, and static-camera clips degenerate to multi-frame depth consensus where GS adds nothing — shrinking the regime where the proposed machinery matters.
  • FIELD VELOCITY: WHOLE, AGILE, and Zero-shot In-Scene Manipulation all appeared within ~8 months; a WHOLE-style world-grounded system with an RGB-only front end would absorb the framing within one review cycle, and by a Nov 2026 CVPR deadline reviewers will ask whether the substrate helps the newest SOTA rather than HORT/ForeHOI.

⚠ Unsound assumptions

  • That a per-frame GLOBAL affine gauge fitted on background pixels transfers to dynamic near-field hand/object pixels — the cited evidence (uniform 0.77x scale, z-only teleports) is consistent with an affine gauge but does not prove affine sufficiency, and the fit is ill-conditioned on narrow-depth-range tabletop backgrounds; depth-net bias is region/depth-dependent.
  • That substrate depth behaves like sensor depth at the injection interface — GT align_depth is noisy-but-unbiased, GS-rendered/corrected depth is smooth-but-biased; pipelines proven exact under GT injection may respond very differently to correlated bias (e.g. render_and_compare anchoring to a uniformly shifted surface).
  • That the pipelines count as 'unchanged' — HORT/ForeHOI output re-gauging and the do-as-i-do anchor flip are modifications; the clean causal framing ('same methods, new input') is only literally true for render_and_compare.

  • That the n=1 kettle-clip oracle result generalizes across objects, grasps, and scenes — the -21% shape residual and surviving HaWoR hand wobble already show gauge is not the whole story even on that clip.
  • That GS bundle adjustment specifically (vs commodity ViPE/MegaSaM/VDA) is needed — unproven, self-identified as make-or-break, and the prior expectation should be that commodity engines get most of the way.
  • That reviewers will accept the homegrown stability protocol (flicker, wiggle ratio, grasp consistency) as headline metrics without community precedent.

Full analysis — problem, technical core, all closest works, complete pressure test

Angle

Plug-in module rather than new pipeline: initialize template-embedded Gaussians from the output of an arbitrary HOI method (render_and_compare, do-as-i-do, ForeHOI, HORT), freeze appearance quickly, then re-optimize only the pose/trajectory parameters against all frames' photometry + smoothness.

Contribution = a universal test-time refiner evaluated across all 4 baselines, plus the jitter-metric suite (depth-correlation, wiggle ratio, acceleration energy, contact flicker) formalized as a benchmark.

Core hypothesis

A shared GS refinement stage recovers most of the stability of full joint optimization (b2/b3) at a fraction of the cost, and improves EVERY baseline's jitter metrics on the HOI4D harness without hurting accuracy — demonstrating that the missing ingredient across the field is joint photometric temporal coupling, not better per-frame estimators.

Why distinct from the other branches

It is evaluated as a delta on N existing methods (a refiner + benchmark paper), not as a standalone reconstruction method; requires no reconstruction-from-scratch and directly weaponizes the user's diagnostic experiments and metrics as the paper's motivation section. Novelty search target: 'test-time Gaussian-splatting refinement of hand/object pose from video'.

Problem statement

Monocular 4D hand-object-interaction reconstruction is temporally broken in a way per-frame metrics do not measure.

Across four heterogeneous state-of-the-art pipelines run on a common harness — feed-forward per-image (HORT), feed-forward video (ForeHOI), compositional optimization (render_and_compare), and generative 6-DoF tracking (do-as-i-do) — hand and object trajectories are estimated per frame with only heuristic temporal coupling, producing the same failure family: object depth slaved to noisy hand depth (measured correlation 0.775), hand depth path-length 7.9x its true net displacement (wiggle ratio), 1.75x frame-to-frame apparent-size flicker of a provably rigid object, and contact that flickers on/off.

Two controlled experiments show the fix is not better per-frame components: swapping the depth backbone (MoGe -> DA3-metric) leaves the flicker unchanged (1.75x -> 1.76x) because the error enters through the anchoring structure, and signal-space smoothing (median+moving-average) suppresses jitter (flicker 0.018 -> 0.005) but cannot correct systematic depth/scale error because it never consults the pixels.

What is missing is (1) a method-agnostic mechanism that restores temporal coherence using the video itself as evidence — without redesigning, retraining, or re-running any estimator — and (2) an evaluation protocol that actually scores temporal stability, since HOI benchmarks report per-frame MPJPE/Chamfer/F-score that are blind to jitter.

We propose both: a plug-in test-time Gaussian-splatting refinement layer that consumes any HOI method's output and re-optimizes only its pose trajectories under a joint all-frame rendering loss, and a temporal-stability benchmark (on the HOI4D GT-depth harness plus GT-motion datasets) that quantifies the field-wide problem and the refiner's uniform improvement of it.

Technical core

A bind-then-refine test-time optimizer with three components.

(1) Canonicalization front-end: a normalized scene contract (already prototyped as compare/scenes/*.npz — hand verts/MANO params, canonical object mesh + per-frame SE(3), or per-frame colored point clouds, camera intrinsics, contact masks, all metric OpenCV camera frame) lifts any method's output to one state: MANO trajectory {theta_t, beta, R_t^h, tau_t^h, per-clip hand scale s_h} + one canonical rigid object with SE(3) trajectory {T_t^o} and global scale s_o.

Mesh-based methods map directly; point-cloud-only methods (HORT) get a canonical object by robust multi-frame registration of the per-frame clouds, which also initializes T_t^o. (2) Template-embedded Gaussian binding, poses frozen (Stage A, ~2k iters, minutes): ~15-25k hand Gaussians parameterized in MANO face-tangent frames and driven by LBS so rendered pixels are differentiable w.r.t.

(theta_t, beta, s_h); ~10-30k object Gaussians rigidly bound to the canonical geometry, transformed by s_o*T_t^o. Appearance (SH color, opacity, scale) is initialized from the method's own textured mesh / colored points and fit briefly over a frame subsample with a per-frame affine exposure code, then FROZEN so it cannot absorb pose error.

(3) Pose-only joint refinement over all frames (Stage B, ~2-4k Adam iters on 8-16-frame minibatches, ~5-10 min/clip on one consumer GPU): trajectories parameterized on a low-pass cubic B-spline/DCT basis (knots every ~5 frames; smoothness partly by construction, variable count O(T/k)), optimized against L = masked L1+D-SSIM photometric on the composited hand+object rasterization (compositing gives occlusion-correct gradients through the grasp, exactly where mask-only losses fail) + per-part silhouette vs the pipelines' existing SAM2/SAM3 masks + optional rendered-depth consistency (GT depth on the harness, metric mono-depth in the wild) + acceleration energy on MANO joints and se(3) log of T_t^o + camera-invariant smoothness on the hand->object relative pose (grasp consistency under camera shake; world frame via HaWoR/HOI4D cameras when available) + contact persistence (hinge on contact-vertex distance to a precomputed object SDF in baseline-contact frames) and non-penetration + a robust Geman-McClure trust region to the baseline trajectory so weakly-observed frames revert to the initialization instead of drifting.

The key observability mechanism: because ONE fixed-size canonical object must photometrically reproject in EVERY frame, the 1/z apparent-size flicker that the diagnostics measured becomes a rendering residual with a nonzero gradient w.r.t. depth — joint multi-frame rigidity converts the jitter diagnostic into supervision, which is precisely what evidence-free smoothing cannot do.

Evaluation: refiner reported as a delta on all four baselines — temporal suite (accel error mm/s^2 vs GT motion on DexYCB/HO3D, wiggle ratio, depth-anchor correlation, apparent-size flicker, contact-persistence) plus accuracy suite (MPJPE, Chamfer, object size/depth error on the HOI4D GT-depth harness, scaled from 1 to ~50 clips) — against OneEuro/Savitzky-Golay/median-MA filters, a learned keypoint smoother, a silhouette-only ablation (no photometric term), and from-scratch per-scene GS reconstruction (BIGS/GHOST) as the cost/quality upper bound; hypothesis: jitter improves for every baseline with no accuracy regression, and monocular depth/scale error shrinks where smoothing provably cannot shrink it.

Key assumptions

  • Baseline outputs land inside the photometric basin of convergence: errors are mostly high-frequency depth/pose noise (as the diagnostics show for RC/daid/ForeHOI), not gross misplacement; for grossly wrong initializations (e.g., HORT's -81% depth) the refiner must rely on multi-frame rigidity + relaxed trust region, and pure monocular scale ambiguity may remain unresolvable without a metric anchor (hand-size prior beta/s_h or metric depth).
  • The object is rigid with constant size (the mechanism converts 1/z size-flicker into depth gradients ONLY under rigidity); articulated/deformable HOI4D categories are out of scope or need per-part extension.
  • Photometric constancy holds well enough inside masks after robust losses + per-frame exposure codes; heavily textureless or specular objects degrade the photometric term toward silhouette-only (an ablation must quantify this floor).
  • Reliable per-part hand/object masks exist (SAM2/SAM3 already run inside all four pipelines, including the point-prompt fix for multi-instance scenes) and mutual-occlusion regions are handled by compositing, not by mask trust.
  • Camera intrinsics are known per method and camera motion can be factored (HaWoR/HOI4D camera poses, or the camera-invariant grasp-relative smoothness term) so temporal priors are imposed in a frame where they are valid.
  • A short appearance fit initialized from the method's own textured geometry, then frozen, is sufficient to prevent appearance from absorbing pose error (the main entanglement risk; mitigated by fitting on a frame subsample and never co-optimizing appearance and pose).
  • Point-cloud-only outputs (HORT) can be canonicalized by multi-frame rigid registration well enough to define one object; failure here reduces the refiner's coverage claim from 4 baselines to 3.
  • The HOI4D GT-depth harness scales from the current single kettle clip to ~50 clips (plus DexYCB/HO3D for GT-motion acceleration error) so the benchmark claim is statistically defensible.
  • A minutes-per-clip test-time budget (~5-10 min on one RTX-4090-class GPU, vs the existing 3 h do-as-i-do budget) is acceptable for the 'refinement layer' framing and is achievable with ~50k Gaussians and spline-parameterized trajectories.
  • Reviewers accept the framing that from-scratch GS-HOI pipelines (BIGS/GHOST/GraG, CVPR'25-'26) are complementary upper-bound comparisons rather than prior art for a method-agnostic pose-only refiner evaluated as a delta on existing methods.

Novelty moderate not pre-empted search: verified-by-search

The two surrounding neighborhoods are individually busy — GS-based HOI/hand reconstruction (BIGS CVPR'25, GHOST'26, DyTact'25, Interaction-aware 4DGS'25, HOLD-descendants) and HOI motion refinement/denoising (TOCH, GeneOH, AAAI'24, DeepSimHO, plug-and-play jitter networks) — and GS-as-pose-refiner is established for cameras/objects (GS-CPR, iComMa, 6DGS, 6DOPE-GS).

But the specific slot (method-agnostic test-time photometric GS refiner evaluated as a delta across HOI pipelines, plus temporal-stability benchmark) appears unoccupied as of this search. Risk is convergence: all ingredients are published and popular, so the window is real but likely short; a reviewer could also frame it as SmoothNet-shape + GS-CPR-mechanism applied to HOI, so the cross-baseline empirical result must carry the paper.

⚠ Failure modes

  • Monocular scale-depth null space guts the headline claim: a uniform object rescale plus depth shift renders (near-)identically, so joint multi-frame rigidity only supervises RELATIVE depth jitter, not systematic depth/scale error. The 'corrects what smoothing provably cannot' claim then holds only when GT/metric depth enters the loss — at which point simple depth-fitting baselines compete and the mechanism story collapses to 'photometric smoothing'.
  • The universal (4/4 baselines) claim likely fails on HORT: -81% depth error and per-frame point clouds with 1.75x size flicker are outside the photometric basin; multi-frame rigid registration of those clouds is itself a hard unsolved subproblem. Non-convex photometric pose landscapes mean the refiner either diverges or the Geman-McClure trust region makes it a no-op — either way the paper's core selling point ('improves EVERY baseline') degrades to 3/4, and reviewers will notice the strongest test case is the one that fails.
  • Jitter metrics are gamed by trivial/learned smoothers — the user's own diagnostic shows median+MA already cuts flicker 0.018->0.005. If GeneOH/TOCH/SmoothNet capture most of the temporal gains at ~zero cost, the 5-10 min/clip optimizer is an expensive smoother, and the paper must win on accuracy deltas that may be within noise at ~50 clips x 4 baselines.
  • Evaluation circularity: the method optimizes acceleration energy, rigidity, and contact persistence, then reports acceleration, size-flicker, and contact-persistence metrics. Only GT-motion accel error (DexYCB/HO3D) and MPJPE/Chamfer/depth error are non-circular — the paper lives or dies on those, and the branch currently has zero evidence it improves them.
  • Appearance bake-in: Stage A fits texture/opacity at the baseline's WRONG jittered poses, then freezes it — pose error is baked into appearance and Stage B refines poses against a corrupted photometric target. Combined with low-texture skin, specular/textureless objects, and motion blur, photometric gradients may be too weak or biased exactly where refinement is needed (ablation floor risk acknowledged but not resolved).
  • Occlusion + symmetry unobservability: during manipulation the object is mostly hand-occluded, and common HOI4D objects (kettle, bottle, mug) are near rotationally symmetric — silhouette and photometric terms then carry almost no object-pose information in the very frames the method claims to stabilize; refined trajectories revert to the trust region (no measurable gain) or drift in the symmetry direction.
  • Benchmark half is largely pre-empted: Jitter/Accel/MPJVE are already standard in video pose papers (e.g., DanceHMR 2026), and HOI benchmarks with trajectory-quality metrics are appearing (DynaHOI). The genuinely new metrics (depth-anchor correlation, apparent-size flicker, wiggle ratio) are diagnostics, not a benchmark contribution reviewers weight heavily; the rigidity assumption also excludes HOI4D's articulated categories, shrinking scope and inviting cherry-picking critique.
  • Scaling compute is dominated by producing INPUTS, not the method: running 4 fragile third-party pipelines (do-as-i-do at ~3h/clip) over ~50 HOI4D clips plus DexYCB/HO3D means hundreds of GPU-hours and pipeline-babysitting before a single refinement result exists; a 1-clip harness to 50-clip benchmark is a large engineering leap the plan treats as an assumption.
  • Over-smoothing true dynamics: spline bases (knots every ~5 frames) plus acceleration penalties imposed in a possibly wrong frame (camera vs world; HaWoR factoring adds its own errors on egocentric HOI4D) can erase genuine fast manipulation motion, HURTING GT-motion accel error — the one non-circular temporal metric.
  • Reviewer framing risk and short window: the paper is compressible to 'SmoothNet paper shape + GS-CPR mechanism + BIGS representation, applied to HOI'. All ingredients are published and popular (HOIGS, GHOST, DyTact, 6DOPE-GS all 2025-26); a from-scratch-fast method like GHOST erodes the speed argument, and convergence within 6-12 months is plausible.
  • Baseline-fairness trap: TOCH refines hands only, GeneOH is trained on different noise distributions, SmoothNet is keypoint-space — every adaptation choice invites 'strawman baseline' or 'unfair comparison' rebuttal ammunition in either direction.

⚠ Unsound assumptions

  • That multi-frame rigidity converts 1/z size flicker into supervision for ABSOLUTE depth/scale — it only constrains relative/temporal variation; the constant scale-depth offset lies in the photometric null space of a monocular rasterizer, so the central 'fixes what smoothing cannot' differentiator is overstated for in-the-wild (no metric anchor) settings.
  • That baseline outputs land inside the photometric basin of convergence — directly contradicted for HORT by the branch's own diagnostics (-81% depth), and untested for gross rotation errors on symmetric objects.
  • That appearance fit at noisy poses and then frozen cannot absorb pose error — fitting appearance FROM wrong-pose renders bakes the error in before the freeze; the mitigation (frame subsample, no co-optimization) does not address this initialization bias.
  • That reviewers will accept BIGS/GHOST/DyTact as 'complementary upper bounds' rather than prior art — the hand representation (MANO-anchored Gaussians, rigid object Gaussians, photometric pose optimization) is essentially identical; the only defensible delta is the method-agnostic-refiner protocol, which is an evaluation framing, not a mechanism.
  • That 'jitter improves with no accuracy regression' clears the CVPR bar — against learned denoisers that also improve jitter cheaply, the paper needs demonstrated accuracy GAINS (depth/scale/MPJPE) on non-circular metrics, a strictly stronger and unproven claim.
  • That the HOI4D harness scales from 1 kettle clip to ~50 clips (and to DexYCB/HO3D) with all 4 baselines runnable end-to-end — the largest unbudgeted engineering assumption in the plan.
  • That SAM2/SAM3 per-part masks are reliable in mutual-occlusion regions — compositing gives occlusion-correct gradients only if the underlying geometry is roughly right, which is circular for badly initialized frames.

Feasibility

data

Public datasets (HOI4D, DexYCB, HO3D) suffice and the GT-depth harness exists — but only for 1 clip today. The real data cost is generating inputs: 4 heterogeneous third-party pipelines must be run at scale (do-as-i-do ~3h/clip), and the rigidity assumption restricts HOI4D to its rigid-object subset. Scaling to ~50 clips x 4 baselines x 2-3 datasets is doable but is weeks of pipeline-wrangling, not a script.

compute

The refiner itself (5-10 min/clip, ~50k Gaussians, spline-parameterized poses on one 4090-class GPU) is realistic and the cheapest part. Dominant cost is baseline-output generation plus ablations and competitor baselines (TOCH/GeneOH/SmoothNet/BIGS-or-GHOST): plausibly 300-800 GPU-hours total — feasible on the user's Vast setup but nontrivial.

evaluation

Weakest leg. Proposed temporal metrics are partly circular (the loss optimizes them) and partly pre-empted (Jitter/Accel/MPJVE standard). Non-circular evidence requires GT-motion accel error and accuracy metrics on DexYCB/HO3D + GT-depth harness, plus fair adaptations of TOCH/GeneOH/SmoothNet and a from-scratch GS upper bound whose code may not be released (GHOST is arXiv'26). Full analysis — problem, technical core, all closest works, complete pressure test

Angle

Scalability/learning angle: accept the multi-hour per-clip cost only offline — run the GS-based pipeline (b1/b2/b3, whichever wins) over large unlabeled video corpora (HOI4D, Ego4D, wild clips) to produce smooth 4D HOI labels, then fine-tune or train feed-forward predictors (HORT/ForeHOI-style, or a video-temporal HOI transformer) on them, with temporal-consistency losses supervised by the GS trajectories.

Core hypothesis

Feed-forward HOI models jitter because their training labels and losses are per-frame; distilling from jointly-optimized 4DGS reconstructions transfers temporal stability into a network that runs in seconds, turning the per-clip compute budget into a one-time data-generation cost.

Why distinct from the other branches

Different deliverable and evaluation: a fast learned model plus a generated dataset, not a per-clip optimizer. It treats the GS pipeline as infrastructure and its contribution is the distillation recipe + demonstrated stability transfer — a NeurIPS/CoRL-flavored story versus the CVPR reconstruction-method stories of b1-b3.

Problem statement

Monocular 4D hand-object-interaction reconstruction is split between two regimes that both fail a deployment need: (1) feed-forward predictors (HORT, ForeHOI) and weakly-coupled multi-stage pipelines (render_and_compare/CHOIR, do-as-i-do) run in seconds-to-minutes but are temporally unstable — per-frame independent estimation yields hand-relative object jitter, floating/penetration flicker, and depth/scale oscillation (on our HOI4D GT-depth harness: +33–43% object-size error and −29% to −81% object-depth error for the feed-forward methods, with visible frame-to-frame instability in all four tested pipelines); (2) jointly-optimized per-clip methods (HOLD-style implicit or 4DGS-based) are smooth and accurate by construction but cost hours per clip (~3h per 5s clip for the best pipeline in our harness), making them unusable online and unscalable as products.

The unsolved problem: obtain the temporal stability and contact plausibility of joint multi-frame photometric optimization at feed-forward inference cost, for category-agnostic unknown objects, and show this transfer scales with unlabeled video rather than with human annotation.

The core hypothesis is that feed-forward jitter is a supervision artifact — existing training labels (DexYCB/HOI4D/HO3D) and losses are per-frame, so no temporal signal exists to learn from — not an architectural limit; hence temporally-coherent pseudo-GT with derivative-level losses should transfer stability into a network that runs in real time.

Technical core

A three-stage data-engine + distillation recipe.

(A) TEACHER (offline, hours/clip, embarrassingly parallel): a template-embedded compositional dynamic Gaussian-splatting optimizer — hand Gaussians bound to MANO mesh faces and driven by LBS from per-frame theta_t and shared beta; object Gaussians rigid, driven by a continuous SE(3) trajectory parameterized as a cumulative B-spline in se(3) (C2-smooth by construction, giving ANALYTIC velocities and accelerations); free background Gaussians absorb the rest of the scene.

Jointly optimized over all T frames with: RGB photometric rendering loss, SAM2 hand/object mask losses, metric-depth alignment (MoGe, or GT depth where available as in the HOI4D harness), world-frame stabilization via HaWoR/SLAM so smoothness is imposed in the world frame not the jittering egocentric camera frame, and contact coupling (attraction between nearest hand/object Gaussians on mask-overlap frames + SDF penetration penalty).

Initialized from the existing perception stack (WiLoR/HaWoR hand, SAM-3D object shape prior). Emits per clip: MANO parameter sequence, canonical object mesh, SE(3) spline, per-vertex contact probabilities, and per-frame per-part confidence scalars (rendered-mask IoU, photometric residual, depth residual).

(B) AUTOMATIC QA GATES that make noisy pseudo-GT usable without human review: rendered-silhouette IoU and 2D-keypoint reprojection thresholds, depth-residual bounds, physics sanity (max penetration depth, contact persistence during grasp), and a held-out-frame render test (frames excluded from optimization must still be explained by the model).

Passing clips enter the corpus with confidence weights; failing frames degrade to 2D-only supervision. (C) STUDENT: a windowed video HOI transformer — frozen-ish ViT per-frame encoder (HaMeR/DINOv2 features), temporal self-attention over 16–32-frame sliding windows, heads for the MANO theta-sequence, object shape tokens (point-cloud or SDF latent decoded once per clip), and per-frame object SE(3) + metric scale.

The novelty-carrying objective distills DERIVATIVES, not just poses: (i) confidence-weighted per-frame MANO/vertex L1 and object-pose geodesic loss; (ii) velocity- and acceleration-matching of hand joints and object pose against the teacher spline's analytic derivatives (the stability-transfer term); (iii) a hand-frame relative-pose consistency loss — the object pose expressed in the hand coordinate frame must match the teacher, directly suppressing the hand-relative jitter/floating all four baselines exhibit; (iv) contact-map BCE from teacher contact labels; (v) mixed-batch training with existing GT datasets (DexYCB/HOI4D labels) to anchor metric accuracy and prevent teacher-bias collapse (e.g., the SAM-3D canonical-aspect-ratio bias that produced −21% kettle size in our harness).

Corpus: HOI4D clips treated as unlabeled (~4k clips), Ego4D hand-object segments, and wild clips.

Evaluation on the existing harness plus DexYCB/HO3D: per-frame MPJPE/Chamfer/F-score AND temporal metrics (SmoothNet-style acceleration error, object-pose jerk, contact-stability rate, penetration), with the two headline plots being (a) stability-retention: student acceleration error approaches teacher's at 100–1000x speedup while per-frame accuracy matches or beats its pretrained baseline, and (b) data-engine scaling: temporal metrics improve monotonically with pseudo-labeled corpus size.

Key assumptions

  • Teacher existence and quality: a GS-based per-clip optimizer (winning b1-b3 variant, or GHOST / Interaction-Aware-4DGS class) matches the best current pipeline's per-frame accuracy on the HOI4D GT-depth harness while being substantially smoother — the engine cannot distill stability or accuracy it does not have.
  • QA-gate validity: automatic proxies (rendered-mask IoU, photometric/depth residuals, penetration/contact-persistence checks, held-out-frame renders) correlate strongly enough with true label error to curate the corpus without human review, and residual noise is zero-mean enough to be handled by confidence weighting.
  • Compute economics: roughly 1-3 GPU-hours per clip times O(10k) clips (10-30k GPU-hours, fully parallelizable, one-time) is affordable, and a corpus of that size is sufficient for stability transfer at 4D-HOI's label dimensionality (scaling analogy from Depth Anything / WHAM holds).
  • Jitter is supervision-limited, not ambiguity-limited: given temporally-coherent labels plus derivative losses, a 16-32-frame windowed transformer can emit smooth trajectories without test-time optimization, and window-boundary seams are solvable by overlap blending.
  • Metric-scale anchoring: the teacher's monocular depth/scale anchoring (MoGe, hand-size prior) is accurate enough that the student's metric heads do not inherit a systematic scale bias — otherwise the student must be trained scale-normalized with a separate scale head (harness already shows monocular methods at +33-43% size error, so this is the riskiest label channel).
  • Teacher-bias containment: mixing pseudo-GT with existing labeled datasets prevents the student from inheriting systematic teacher failure modes (segmentation locking onto wrong objects, SAM-3D canonical-shape aspect bias, spline over-smoothing of genuinely fast motions like regrasps).
  • World-frame reliability: HaWoR/SLAM camera stabilization is accurate enough on egocentric and wild footage that smoothness constraints are imposed in the world frame — otherwise camera shake gets baked into the labels as object motion.
  • Novelty window (verified July 2026): published GS-HOI works (GHOST, Interaction-Aware 4DGS, CHOIR) are per-clip reconstruction methods only; pseudo-4D annotation engines (NeoVerse, Any4D) are scene-level, not parametric hand-object; prior HOI pseudo-labeling (Liu et al. CVPR'21) filters per-frame predictions for known objects — no published work distills jointly-optimized 4D HOI reconstructions with derivative-level supervision into a feed-forward model, but this window may close within 1-2 conference cycles.

Novelty crowded not pre-empted search: verified-by-search

Every component lane is now heavily populated and converging: GS-based per-clip HOI teachers (Interaction-Aware 4DGS Nov'25, GHOST Mar'26, BIGS CVPR'25), feed-forward HOI students (HORT ICCV'25, ForeHOI Feb'26 — already claiming ~100x-over-optimization speedups), temporally-consistent world-frame HOI pipelines (EgoGrasp Jan'26), and — most critically — web-scale automated 4D HOI data engines (EgoInfinity Jun'26, VITRA ICRA'26) appeared within the last 9 months.

The exact intersection (derivative-level distillation of a jointly-optimized 4DGS teacher into a real-time video HOI reconstructor, evaluated on stability transfer) is still unoccupied, but with a data engine and fast GS teachers both published in 2026, the 1-2-cycle window the proposal itself flags is real and shrinking; expect a direct competitor within ~2 cycles.

Full novelty delta

No found work distills jointly-optimized, temporally-coherent 4D HOI reconstructions into a feed-forward video reconstruction model with derivative-level supervision.

The branch's surviving novelty is precisely: (1) teacher = compositional template-embedded 4DGS with C2 se(3)-spline object trajectories whose ANALYTIC velocities/accelerations become supervision targets (no prior HOI pseudo-labeler supervises derivatives — Liu'21, VITRA, EgoInfinity all supervise poses/states only); (2) hand-frame relative-pose consistency loss targeting hand-relative object jitter specifically; (3) the scientific claim that HOI temporal stability is a property of supervision, not architecture or test-time optimization, demonstrated via stability-retention (student acceleration error vs teacher at 100-1000x speedup) and corpus-scaling curves on temporal metrics.

However, the delta has narrowed materially: EgoInfinity (Jun 2026) already owns 'web-scale 4D HOI data engine with automatic QA' as a headline — this branch can no longer claim the first HOI data engine and must be positioned as 'first distillation of joint-optimization temporal coherence into a real-time HOI reconstructor', with EgoInfinity/VITRA labels as ablation baselines (per-frame-pipeline pseudo-GT vs jointly-optimized pseudo-GT) to prove the joint-optimization teacher is what transfers stability.

If that ablation fails — i.e., modular per-frame labels plus simple smoothing distill equally well — the contribution collapses to an incremental loss recipe.

⚠ Failure modes

  • The necessity ablation is the whole paper and it can fail: if per-frame pseudo-labels (EgoInfinity/VITRA-style, or the team's own 2.5-min render_and_compare) plus a spline/SmoothNet fit — which also yields analytic derivatives — distill stability equally well, the contribution collapses to 'we added velocity/acceleration losses', an incremental loss recipe no top venue accepts. The proposal itself concedes this, and there is currently zero pilot evidence that jointly-optimized labels transfer stability better than smoothed per-frame labels.
  • A near-free trivial baseline may match the headline result: existing DexYCB/HO3D/HOI4D GT labels ARE temporally sequential, so derivative losses can be computed on real GT today with no data engine; and post-hoc output smoothing (SmoothNet/OneEuro on HORT outputs) crushes acceleration error at ~zero cost. The core hypothesis statement ('no temporal signal exists to learn from') is factually wrong as written — the missing thing is temporal LOSSES and wild-data scale, not temporal labels. If 'student + derivative losses on existing GT + inference smoothing' lands near the distilled student, the 10-30k-GPU-hour engine bought nothing measurable.
  • Teacher does not exist and its accuracy is unproven off-harness: the winning b1-b3 4DGS teacher is an unbuilt prerequisite (sequential two-paper dependency), and the only exact results in the harness required GT depth injection, which is unavailable on Ego4D/wild clips — precisely the corpus that justifies the engine. On monocular wild egocentric video (motion blur, hand occluding the object most of the time, textureless/specular objects, MoGe+HaWoR error stacking), a photometric 4DGS teacher may be smooth-but-systematically-wrong, and the student inherits smooth hallucination. Smoothness is easy; smooth AND correct in the world frame from monocular RGB is the open problem being assumed away.
  • Motivation numbers rest on n=1: the entire jitter/scale-error narrative (+33-43% size, -29 to -81% depth, all four pipelines unstable) comes from a single HOI4D kettle clip. Reviewers at CVPR will not accept a one-clip harness as evidence of the problem, let alone as the evaluation; a proper multi-clip multi-category temporal-stability benchmark must be built first, which is itself substantial unfunded work in this plan.
  • QA gates validate image space, not 3D: rendered-mask IoU, photometric residual, and held-out-frame renders are all satisfiable by geometrically wrong Gaussians (floaters, wrong depth, wrong aspect ratio) — GS is notorious for this, and monocular video's tiny baseline makes held-out-frame tests weak. The harness's own SAM-3D canonical-aspect bias (-21% kettle size) would pass every proposed gate. Confidence weighting handles variance, not bias; the biases are systematic, so the 'zero-mean residual noise' assumption fails exactly where it matters (scale/depth — the channels already flagged as riskiest).
  • Acceleration-error headline metric is gameable and the GT for it is shaky: any over-smoothed predictor wins acceleration error; without a paired responsiveness metric (accuracy during regrasps/fast motion, tracking lag), 'stability retention' is a rigged plot reviewers will attack. Meanwhile HOI4D object-pose GT is itself annotation-noisy, so measuring jerk against it actively rewards over-smoothing; only DexYCB/HO3D (lab, known objects — the distribution the engine was supposed to escape) give trustworthy derivatives.
  • Compute-times-yield economics: 1-3 GPU-h/clip x O(10k) clips assumes near-100% QA pass rate; realistic yield on wild egocentric footage (SLAM failures, wrong-object segmentation — already seen once in the harness, occlusion-dominated grasps) could be 20-40%, pushing effective cost toward 30-80k GPU-hours for a corpus large enough to draw a credible scaling curve. If the budget forces a 2-3k-clip corpus, the 'data-engine scaling' headline plot (the CVPR hook) degenerates to two or three points.
  • Crowdedness and window: EgoInfinity (Jun 2026) already owns 'web-scale automated 4D HOI data engine with QA', VITRA owns the pseudo-label scaling curve for hands, ForeHOI owns 'feed-forward replaces slow HOI optimization at 100x', and GHOST's 13x-faster GS teacher erodes the offline-only premise. The surviving sliver (derivative-level distillation from a jointly-optimized teacher, stability-transfer claim) is real but narrow, and a two-cycle build timeline (teacher paper first, then this) very plausibly loses the race to an EgoInfinity follow-up that simply trains a reconstruction student on their existing labels.
  • Scope: teacher pipeline + QA system + new temporal benchmark + video student + scaling study is 2-3 papers of engineering surface compressed into one; in 8 pages every component gets attacked (teacher vs GHOST/Interaction-Aware-4DGS, student vs EgoGrasp/ForeHOI, engine vs EgoInfinity), and the mixed-batch GT anchoring needed to fix metric scale simultaneously confounds attribution of the stability gains to the pseudo-GT.

⚠ Unsound assumptions

  • 'Existing training labels have no temporal signal' — false as stated: DexYCB, HO3D, and HOI4D provide temporally-sequential GT on which derivative losses are computable today; the honest claim is only about loss design and wild-data diversity, which is a much weaker motivation for a 10-30k GPU-hour engine.
  • 'Jitter is supervision-limited, not ambiguity-limited' — monocular depth/scale oscillation is partly irreducible ambiguity; a smooth-labeled student can resolve it by emitting temporally-consistent but arbitrary depth (stable hallucination), so stability transfer conflates variance reduction with correctness and the evaluation as designed cannot distinguish them.
  • 'QA-gate proxies correlate with true 3D label error and residual noise is zero-mean' — image-space gates are blind to systematic 3D bias (the harness's own -21% SAM-3D aspect bias passes all gates), and the dominant teacher errors (scale, depth, canonical shape) are biases, which confidence weighting cannot average away.
  • 'Teacher matches best per-frame accuracy while being smoother' — unverified: the harness's accurate configurations required GT-depth injection unavailable in the wild, the 4DGS teacher is unbuilt, and the 3h/clip figure comes from a different method; assuming the b1-b3 winner exists and generalizes off HOI4D is assuming the hard paper already succeeded.
  • 'Depth Anything / WHAM scaling analogy holds' — dense per-pixel depth with strong 2D inductive biases scales very differently from a structured ~60-dim MANO+SE(3) output; O(10k) clips of correlated egocentric footage is orders of magnitude less diverse data than those precedents used, so monotonic scaling curves on temporal metrics are hoped-for, not supported.
  • 'HaWoR/SLAM world-frame stabilization is reliable on wild egocentric video' — on Ego4D-style footage SLAM drift and rolling shutter routinely fail; wherever it fails, camera shake is baked into pseudo-GT as object motion, i.e., the engine manufactures exactly the jitter it claims to remove, and no proposed QA gate detects it.

MEDIUM. HOI4D (~4k clips) is in hand and already harnessed; Ego4D hand-object segments are accessible. evaluation

No established HOI temporal-stability benchmark exists; headline metrics (acceleration error, jerk, contact stability) are self-defined, gameable by over-smoothing, and must be measured against GT whose own derivatives are noisy (HOI4D) or in-lab (DexYCB/HO3D, defeating the wild-generalization claim). The decisive experiments — (a) jointly-optimized vs smoothed-per-frame pseudo-GT ablation, (b) derivative-losses-on-existing-GT baseline, (c) student-plus-output-smoothing baseline — are all cheap for competitors/reviewers to demand and any one of them can nullify the contribution.

Verdict: maybe — The surviving delta (derivative-level distillation from a jointly-optimized 4DGS teacher, with a stability-is-supervision claim) is genuinely unoccupied, and the deliverable shape fits CVPR's data-engine precedent. With EgoInfinity already owning the data-engine headline and a plausible follow-up student within 1-2 cycles, do NOT commit the 10-30k GPU-hour engine now. Pursue at scale only if joint optimization wins that pilot decisively; otherwise drop and keep the teacher as the standalone contribution.

Full analysis — problem, technical core, all closest works, complete pressure test

Angle

Two-stage decoupling: solve temporal coherence FIRST in a template-free representation (persistent/tracked dynamic Gaussians a la Dynamic 3DGS / Shape-of-Motion / MoSca), THEN fit semantic templates (MANO hand, SAM-3D object mesh, 6-DoF trajectory) to the already-smooth Gaussian motion field. The GS stage is a drop-in replacement for per-frame HaWoR/depth estimators as the source of 3D evidence.

Core hypothesis

Photometric consistency enforced jointly across all frames makes persistent Gaussian trajectories far smoother than per-frame monocular estimates (HaWoR depth wiggle ratio 7.9); fitting MANO/SE(3) to these trajectories (Procrustes/ICP + robust registration, seeded by per-frame estimates) inherits that smoothness by construction, beating trajectory filtering on jitter metrics without losing HOI4D accuracy.

Why distinct from the other branches

Cleanly sequential (reconstruct-then-parse): no template is inside the GS optimization loop, so it works even when MANO/mesh initialization is bad, and the GS stage is method-agnostic. Contrasts with b2/b3 where templates ARE the GS parameterization, and with b5 where GS refines an existing HOI solution rather than being the primary reconstruction.

Problem statement

Monocular 4D hand-object-interaction reconstruction — recovering a metric MANO hand trajectory plus an unknown rigid object's shape and SE(3) trajectory from one RGB video — is today assembled from per-frame estimators that are only weakly coupled in time.

On a GT-depth HOI4D harness, all four representative pipelines (render_and_compare, do-as-i-do/HaWoR, ForeHOI, HORT) fail temporally because each frame's 3D evidence is independently wrong: HaWoR hand depth traverses ~8x more z-path than the hand actually moves (wiggle ratio 7.9: 0.53 m path vs 0.067 m net), HORT's hand centroid teleports ~1.15 m in z between frames, and monocular object depth is biased -29% to -81%.

Two controls show the failure is structural: swapping in a better metric-depth model (DA3) leaves the object's apparent-size swing unchanged (1.75x -> 1.76x), and output-space filtering (median(9)+moving-average(7)) suppresses only the high-frequency flicker (0.018 -> 0.005) while the low-frequency depth swing survives (1.75x -> 1.59x) — smoothing cannot correct biased evidence, only hide its jitter.

The problem: within the already-accepted multi-hour offline per-clip budget (do-as-i-do spends ~3 h on a 5 s clip), make temporal coherence a property of the 3D evidence itself — estimated jointly across all frames — while matching per-frame accuracy (hand MPJPE, object size/depth/ADD) on the same harness.

Technical core

A two-stage reconstruct-then-parse pipeline in which a band-limited, template-free persistent-Gaussian motion field replaces per-frame estimators as the sole source of 3D evidence, and templates are extracted from it afterwards by robust registration.

Stage 0 (priors, per clip): camera poses (HOI4D-provided; MASt3R-SLAM/MegaSAM in the wild); point-prompted SAM2 hand/object masks (text prompts already shown to lock onto wrong instances); CoTracker3/TAPIR long-range 2D tracks on the foreground; per-frame metric monocular depth (DA3-metric) aligned by a SINGLE per-sequence affine (scale, shift); HaWoR per-frame MANO only as a seed (median beta, one canonical-frame pose).

Stage 1 (temporal denoiser): a MoSca-style persistent dynamic-Gaussian reconstruction of the foreground. Canonical Gaussians (unprojected from masked depth at keyframes) are skinned by dual-quaternion blending to a sparse SE(3) motion scaffold (~100-200 nodes hand group, ~20-50 object group, grouped by lifted masks — still no template).

The critical design choice: node trajectories live in a low-rank temporal basis (cubic B-splines, knot spacing 0.25-0.4 s, i.e. a <=4-8 Hz band limit at 30 fps), so frame-rate jitter is UNREPRESENTABLE — smoothness is a property of the parameterization, not a penalty; simultaneously, joint photometric consistency (L1+D-SSIM) of the SAME persistent Gaussians across all frames triangulates absolute depth from ego-motion + in-hand object-rotation parallax, removing the low-frequency depth bias that filtering provably cannot (the residual 1.59x swing).

Additional losses: mask rendering, sequence-affine depth prior, 2D-track reprojection (long-range correspondence through occlusion), ARAP/isometry on scaffold edges, and a soft intra-object rigidity term whose residual is kept as a regrasp/articulation diagnostic.

Stage 2 (parse — templates never inside the GS loop): (a) Object SE(3) trajectory: because persistent Gaussians give explicit cross-time correspondence, per-frame pose is a CLOSED-FORM weighted Umeyama/Procrustes (scale fixed to 1) between canonical and frame-t object-Gaussian positions, robustified by IRLS/Huber against mask bleed and non-rigid stragglers — no ICP, no learned matcher, no pose network.

Object shape: TSDF-fuse GS depth renders expressed in the recovered object frame (in-hand scanning for free), optionally registering a SAM-3D mesh once for a CAD-like output.

(b) Hand: fit MANO once in the canonical frame (HaWoR seed), bind each hand Gaussian to its nearest MANO surface point (barycentric + LBS weights), then solve theta(t) and root SE(3)(t) per frame by Levenberg-Marquardt on Huber point-to-correspondence residuals with only a weak pose prior and NO temporal smoothness term — the headline ablation shows adding one changes nothing because the evidence is already band-limited, whereas per-frame baselines need filtering and still keep their low-frequency bias.

Metric scale is resolved once per sequence via the depth affine plus a canonical hand-size prior on beta (~0.19 m — the same fix that recovered render_and_compare's 0.77x hand).

(c) Contact polish: contacts detected from the stage-1 motion field itself (sustained proximity + near-zero relative tangential velocity between hand Gaussians and object surface), then a short joint refinement with contact attraction, MANO-vs-object-SDF non-penetration, and grasp-preserving coupled updates (hand and object moved by the same delta).

Evaluation: HOI4D rigid categories with GT align_depth + GT object pose + MANO GT — accuracy (hand MPJPE/MRRPE, object CD/ADD-S, size/depth error) AND temporal metrics (wiggle ratio, acceleration error, apparent-size flicker and swing, contact stability, penetration), against the four pipelines raw and with ORACLE-TUNED filters (OneEuro/median+MA/spline/Kalman) — the decisive control — plus template-in-the-loop GS/implicit comparators (BIGS, HOLD) and DexYCB/HO3D for cross-paper comparability.

Key assumptions

  • Parallax sufficiency: egocentric camera motion plus in-hand object rotation give enough effective baseline for joint photometric consistency to anchor absolute depth better than any per-frame metric-depth prior; on low-parallax segments the method must degrade gracefully to sequence-affine-aligned depth-prior quality rather than diverge.
  • Monocular dynamic-GS optimization (MoSca / Shape-of-Motion class) converges on egocentric HOI clips despite hand texture-poverty, motion blur, and mutual hand-object occlusion, provided masks, long-range 2D tracks, and depth priors; scaffold persistence carries occluded Gaussians well enough that per-frame registration has usable support on both sides of every occlusion.
  • Smoothness transfer: because cross-time correspondence is persistent by construction (no per-frame re-matching), Procrustes/IK against band-limited trajectories yields band-limited template parameters — no correspondence flicker at contact boundaries; this is the load-bearing mechanism behind 'smooth by construction' and must hold empirically.
  • Band-limit validity: 0.25-0.4 s spline knots (<=4-8 Hz) sit above genuine HOI4D manipulation dynamics but below the jitter band (HaWoR wiggle at frame rate); if real motion has faster components the basis clips them (tunable, but a bias-variance knob that must be reported).
  • Object rigidity within the clip (scope: HOI4D rigid categories — kettle, bottle, mug, toy car); regrasps and articulated objects are detected via the non-rigid Procrustes residual but explicitly out of scope to reconstruct.
  • Camera poses are available or recoverable: HOI4D provides them; in-the-wild results assume egocentric SLAM (MASt3R-SLAM / MegaSAM) succeeds on handheld HOI clips.
  • Segmentation lift is reliable: point-prompted SAM2 masks (text prompts already shown to grab the wrong instance on HOI4D) group Gaussians into hand/object well enough that IRLS absorbs residual mask bleed.
  • Seeding is cheap: one decent HaWoR frame (median beta + canonical pose) suffices to initialize the MANO binding, and metric scale is resolvable once per sequence from the depth affine plus the ~0.19 m canonical hand-size prior that already fixed render_and_compare's 0.77x hand.
  • Compute budget: multi-hour offline per-clip optimization is acceptable — already the operating point (do-as-i-do ~3 h per 5 s clip on the same harness), with the GS stage estimated at 1-2 h/clip on a single modern GPU.

Novelty crowded not pre-empted search: verified-by-search

Monocular per-clip HOI reconstruction is one of the fastest-moving corners of 3D vision: HOLD (CVPR24), DyTact, BIGS (CVPR25), Interaction-Aware 4DGS (11/25), GraG (04/26), CHOIR (05/26), THO (03/26), plus feed-forward lines (HORT, ForeHOI) and hand-trajectory lines (Dyn-HaMR, HaWoR) — several explicitly claiming temporal coherence with acceleration-error metrics in the last 8 months.

The specific reconstruct-then-parse cell (template-free GS evidence -> post-hoc template registration) and the oracle-filter temporal benchmark are still unoccupied, but concurrent-work risk before a Nov 2026 CVPR deadline is high — GraG and CHOIR appeared within the last 3 months alone.

Full novelty delta

No published work makes a template-free, band-limited (spline-basis motion-scaffold) persistent-Gaussian reconstruction the SOLE 3D evidence and then extracts semantic templates from it post-hoc — closed-form per-frame Umeyama/Procrustes on persistent object-Gaussian correspondences plus skinning-bound MANO trajectory IK with no temporal smoothness term.

Existing Gaussian HOI systems either put templates inside the optimization (BIGS, HOLD, DyTact, MANUS) or track a frozen Gaussian shape per-frame with explicit temporal-smoothness PENALTIES (GraG) — i.e., smoothness as regularization on outputs, whereas this branch makes frame-rate jitter unrepresentable in the evidence itself and claims smoothness transfers to templates by construction.

The second genuinely open contribution is the evaluation: a temporal-coherence benchmark on HOI4D GT depth with ORACLE-TUNED output filters on four per-frame pipelines as the control, plus the high-frequency-flicker vs low-frequency-depth-bias decomposition (filtering fixes 0.018->0.005 flicker but not the 1.59x swing) — no found paper isolates that distinction.

Caveats to the claim: GraG (Apr 2026) already owns 'temporally stable, template-light Gaussian HOI tracking with acceleration metrics' and is 6.4x faster than HOLD, so the 'first temporally coherent Gaussian HOI' framing is dead — the paper must be positioned as evidence-side band-limiting + reconstruct-then-parse vs GraG's track-with-penalties, and must ablate against a smoothness-penalty variant; Interaction-Aware 4DGS already does template-free 4DGS on HOI4D (but stops before parsing); MoSca supplies Stage 1 nearly wholesale, so novelty rests on the parsing stage, the band-limit argument, and the benchmark rather than the reconstruction machinery.

⚠ Failure modes

  • Core mechanism may be theoretically hollow: for a DYNAMIC foreground object, monocular photometric consistency cannot triangulate absolute depth — a rigid moving object has an irreducible size/depth/translation ambiguity under a moving monocular camera (scaling object size and its z-trajectory together re-explains all images). Ego-motion parallax anchors only the STATIC background; in-hand rotation parallax recovers object SHAPE up to scale, not distance. So Stage 1 will make apparent size CONSISTENT nearly by construction (frozen canonical Gaussians => the 1.75x swing metric collapses trivially) while the absolute depth trajectory stays anchored to the same biased DA3 prior (-29% to -81%) via the sequence affine. Result: temporal metrics improve, ADD/depth-error does not, and reviewers correctly read the headline 'removes the bias filtering cannot' as unsupported — consistency was achieved, correctness was not.
  • The killer ablation the proposal does not include may nullify the entire Gaussian stage: fit the SAME cubic-B-spline band-limited basis directly to template parameters (MANO theta/root + object SE(3)) with the same photometric/mask/track/depth losses — i.e., band-limited template-space bundle adjustment (essentially HOLD/BIGS with a spline basis, seeded exactly as proposed with HaWoR + SAM-3D). If that simpler baseline matches on jitter AND accuracy, the reconstruct-then-parse architecture is unnecessary machinery and the paper's central claim ('evidence-side band-limiting, templates outside the loop') reduces to a parameterization trick that works equally well template-in-the-loop. An AC will demand this ablation and it is genuinely likely to tie.
  • The band-limited-basis vs smoothness-penalty distinction (the delta against GraG) may be empirically indistinguishable: a well-tuned acceleration penalty realizes the same low-pass transfer function as spline knots. The required ablation (spline basis vs penalty variant, same losses) plausibly shows no significant difference, collapsing the main framing against the closest prior work to 'we chose a different regularizer.'
  • MoSca/Shape-of-Motion-class optimization is brittle on exactly this footage: texture-poor fast-moving hands, motion blur, fingers self-occluding, object >50% occluded by the grasp. CoTracker3 tracks break at blur/occlusion; 20-50 scaffold nodes on a mostly-hidden object are under-constrained; DQB skinning tears at the hand-object boundary. Expect a meaningful per-clip failure rate (divergence or mush) that forces either cherry-picking (reviewers punish) or honest success-rate reporting that undercuts the 'drop-in replacement for per-frame estimators' claim. MoSca also needs per-scene hyperparameter babysitting, contradicting 'method-agnostic.'
  • Smoothness-transfer breaks precisely where it matters: at contact/occlusion boundaries the registration SUPPORT SET churns (mask bleed flips boundary Gaussians between hand and object groups, occluded Gaussians drop in/out of IRLS inliers), reinjecting frame-rate jitter into Procrustes/IK outputs even though individual trajectories are band-limited. The headline 'no temporal smoothness term needed' ablation can fail exactly at contact events — the frames the HOI community cares about.
  • Hand accuracy may regress: MANO IK driven only by 3D Gaussian-correspondence residuals discards image-space keypoint evidence; a single canonical-frame binding (one HaWoR pose, median beta) propagates any canonical-frame error globally; and the 4-8 Hz band limit clips genuine fast finger articulation during grasp establishment/regrasp. Plausible outcome: wins on wiggle/acceleration, loses on MPJPE vs Dyn-HaMR/filtered HaWoR — read as a smoothness-accuracy tradeoff, not a win.
  • Crowding/scoop risk is acute: GraG (04/2026) already owns 'temporally stable template-light Gaussian HOI tracking' with acceleration metrics at 36 min/100 frames; CHOIR (05/2026) owns 'temporally consistent 4D HOI via multi-stage per-clip optimization'; Interaction-Aware 4DGS already does template-free 4DGS on HOI4D. Another 4-5 months of concurrent work land before the Nov 2026 deadline. The surviving delta (parse-after vs track-with-penalties + oracle-filter benchmark) is a framing-level contribution reviewers can dismiss as 'MoSca + Umeyama + MANO IK — a combination of known components.'
  • Benchmark contribution is weaker than claimed: THO and GraG already report acceleration/temporal metrics for HOI, so 'first temporal-coherence benchmark' is dead as stated; what remains is the oracle-filter control and the flicker-vs-swing frequency decomposition — a strong ANALYSIS section but not a standalone contribution that carries a CVPR paper, and it is built on HOI4D GT (align_depth holes at hand boundaries, known-noisy object pose annotations) which invites disputes about whether measured 'jitter' partly lives in the GT.
  • Systems integration burden vs timeline: SAM2 + CoTracker3 + DA3 + MoSca-variant + Procrustes/IRLS + MANO IK + TSDF fusion + contact refinement, then 4 per-frame baselines with oracle filter sweeps, plus HOLD (~10.5 h/clip) and BIGS reproduction, plus DexYCB/HO3D for comparability — at 1-2+ h/clip over the dozens of clips needed for a credible benchmark, this is multi-GPU-weeks of compute and months of brittle glue engineering with ~4.5 months to the deadline.
  • Scope narrowness: rigid HOI4D categories only, regrasps/articulation explicitly out of scope, single-hand implicitly assumed; GraG evaluates HO3Dv3+HOT3D and handles the same setting faster — reviewers will ask why the 3-hour offline pipeline is worth it when the fast concurrent method exists and the accuracy delta is unproven.

⚠ Unsound assumptions

  • 'Parallax sufficiency' as stated is unsound, not merely risky: joint photometric consistency over a moving monocular camera constrains a dynamic rigid object's depth only up to the size/depth/motion ambiguity; the claimed mechanism for removing the low-frequency 1.59x residual swing (triangulation from ego-motion + in-hand rotation) does not exist for the dynamic foreground. The honest version — 'we enforce consistency and inherit absolute scale from the depth affine + hand-size prior' — is a much weaker claim and must replace the current one.
  • 'Smoothness transfer by construction' assumes a temporally stable registration support set; occlusion- and mask-bleed-driven inlier churn at contact boundaries violates it exactly where evaluation focuses. It is an empirical hope, not a construction.
  • 'Band-limit validity' assumes genuine HOI4D manipulation dynamics live below 4-8 Hz; contact transients and grasp-establishment finger motion plausibly do not, and the assumption is being used to justify removing the very evaluation frames where per-frame methods fail worst.
  • 'Seeding is cheap' (one canonical HaWoR frame + median beta) is fragile: canonical-frame selection is itself a failure point, and errors in that single binding propagate to every frame with no image-space correction path in the proposed IK.
  • 'The GS stage is a drop-in, method-agnostic replacement' contradicts the known per-scene fragility and tuning burden of MoSca-class optimization on adversarial footage (blur, texture-poor skin, heavy mutual occlusion).
  • Implicit assumption that matching per-frame accuracy while winning temporal metrics clears the CVPR bar in 2026: with GraG/CHOIR/THO all claiming temporal coherence, reviewers will likely require an accuracy win or a decisive mechanism ablation, not parity plus smoothness.
  • Implicit assumption that the Gaussian intermediate is necessary at all — untested against band-limited template-space joint optimization with identical losses and seeds (the most dangerous missing baseline in the plan).

Feasibility

data

Good. HOI4D with GT align_depth, object pose, and MANO is in hand and the eval harness plus four baseline pipelines already run (compare/hoi4d exists in-repo); no new capture needed. Gaps: HO3D/DexYCB runs needed for cross-paper comparability (GraG reports on HO3Dv3/HOT3D), HOI4D GT noise (depth holes at hand boundaries, imperfect object poses) threatens the credibility of fine-grained jitter metrics, and rigid-category filtering shrinks the clip pool.

compute

Marginal on the stated setup. 1-2 h/clip (optimistic for MoSca-class + parse + contact refinement) x ~50-100 clips x (method + ~6 ablations incl. spline-vs-penalty and template-space-BA) + oracle filter sweeps on 4 baselines + HOLD at ~10.5 h/clip is multi-GPU-weeks; doable with a small cluster or sustained vast.ai spend, painful on one GPU. The real cost is engineering time: 6+ brittle third-party components integrated in ~4.5 months to the Nov 2026 deadline.

evaluation

Strongest asset and biggest trap. The oracle-tuned-filter control and flicker-vs-swing frequency decomposition are genuinely good experimental design and already partially executed. But the decisive tests cut both ways: (1) does Stage 1 actually reduce ABSOLUTE object depth error vs sequence-affine-aligned DA3, or only variance around the same bias — measurable on GT depth in week one; (2) does band-limited template-space optimization without Gaussians tie the full pipeline. If either goes the wrong way the paper's core claim dies, so evaluation is feasible but has high self-refutation risk. Per-clip success rates must be reported to preempt cherry-picking accusations.

Verdict: maybe — The problem analysis (filtering fixes high-frequency flicker but not low-frequency depth bias) is genuinely strong and grounded in the user's own harness, and the reconstruct-then-parse cell is technically unoccupied. But the branch has one likely-fatal technical flaw — monocular photometric consistency cannot fix absolute depth bias for a dynamic object, so the mechanism advertised as the cure for the 1.59x residual swing does not exist in principle, only consistency does — and one likely-fatal strategic flaw: GraG/CHOIR/THO have crowded the temporal-coherence-for-HOI claim in the last 8 months, leaving a delta (basis vs penalty, parse-after vs track-with) that a plausible ablation shows is a wash. Do not commit to the full build. Run a 2-3 week kill-test first: (a) MoSca-class Stage 1 on 3-5 HOI4D clips — measure absolute object depth error and swing vs sequence-affine DA3 on GT depth; (b) band-limited template-space joint optimization (same losses, no Gaussians) as the null hypothesis. Pursue only if (a) shows a real absolute-depth win and (b) loses to the Gaussian pipeline; otherwise pivot the paper toward the analysis/benchmark contribution or drop the branch.

Full analysis — problem, technical core, all closest works, complete pressure test

Angle

Analysis-by-synthesis where the ONLY free variables are MANO pose/shape/global trajectory, object 6-DoF trajectory, and Gaussian appearance attached to the templates — a GART/GaussianAvatar-style rig extended to two interacting entities with unknown object geometry (Gaussians initialized on the SAM-3D mesh, optionally refining it).

Photometric loss across ALL frames jointly + trajectory smoothness priors replace per-frame keypoint/depth losses.

Core hypothesis

Backpropagating a multi-frame differentiable-splatting photometric loss into low-dimensional template parameters is a fundamentally stronger temporal coupling than any post-hoc filter or per-frame render-and-compare: jitter cannot exist unless it improves photometric fit in every frame, so the solution is stable by construction while pixel-accurate.

Why distinct from the other branches

Templates are the parameterization inside the GS loop (low-DOF, semantically constrained), versus b1 where GS is free-form and templates come after. This is the direct 'GaussianAvatar-for-HOI' framing and the branch whose novelty hinges most on whether hand-avatar-GS papers already cover interaction with unknown objects.

Problem statement

Given a monocular (optionally egocentric, moving-camera) RGB(-D) video of a hand manipulating an unknown rigid object, recover a metric, world-frame, temporally consistent 4D reconstruction — MANO shape + pose trajectory, object geometry, and object SE(3) trajectory — under an offline per-clip compute budget.

Every existing pipeline, whether feed-forward (HORT, ForeHOI), render-and-compare, diffusion-guided (do-as-i-do), or Gaussian-splatting-based (BIGS CVPR'25, GHOST'26, Grasp-in-Gaussians'26), ultimately keeps PER-FRAME pose variables that are at best weakly coupled by smoothness losses or post-hoc filters; empirically (our HOI4D GT-depth harness) this yields object size errors of +33–43%, absolute depth errors of −29% to −81% for monocular methods, and frame-to-frame jitter/floating of the grasped object in all four tested pipelines — artifacts a filter cannot fix because it never sees pixels.

The problem: re-spend the already-accepted multi-hour budget on ONE joint spatio-temporal optimization in which temporal coherence and hand-object attachment are structural properties of the parameterization, while matching or beating per-frame accuracy on metric world-frame benchmarks.

Technical core

Analysis-by-synthesis over the WHOLE clip where the only geometric unknowns are low-DoF template trajectories, and time-invariant Gaussian appearance rigged to the templates turns texture into a self-supervised tracker (any jitter misaligns the shared texture in every frame and raises the loss).

(1) STATE: hand = shared MANO beta + per-joint rotation trajectories as cumulative B-splines (knots at 4–8 Hz) + wrist se(3) spline; N_h Gaussians bound to MANO faces (barycentric anchor + normal offset, LBS-skinned, GART-style pose-corrective blendshapes).

Object = canonical SAM-3D mesh (from the best-visibility frame; global scale is a free variable) with face-anchored Gaussians (bounded local offsets) + optional per-vertex displacement field with Laplacian/ARAP regularization to correct SAM-3D's aspect-ratio bias (measured −21% on our kettle clip).

(2) CONTACT-FACTORIZED OBJECT TRAJECTORY — the key mechanism: contact segments are seeded from SAM2 mask adjacency + init proximity; during a held segment k, T_obj(t) := T_wrist(t) ∘ G_k with a SINGLE latent grasp transform G_k per segment plus a heavily-regularized slow drift spline for in-hand adjustment; during free segments T_obj(t) is a cumulative se(3) B-spline (continuous-time-SLAM parameterization imported into HOI); segment boundaries get optimizable soft blending.

Hand-relative jitter and 'floating' are thus impossible by construction during grasp — not penalized, unrepresentable.

(3) LOSSES, summed over frame minibatches spanning the clip: composited depth-sorted rasterization of both Gaussian sets → masked L1 + D-SSIM photometric with per-frame affine exposure; per-entity silhouette vs SAM2 alpha; DINOv2 feature-metric loss for specular/textureless robustness; depth term (GT depth on HOI4D, metric-mono depth in the wild) resolving absolute scale/depth; robust low-weight 2D keypoint anchor (Geman-McClure so per-frame detector jitter is not re-imported); SDF penetration hinge + fingertip attraction during held phases; small acceleration penalties on spline knots.

(4) SCHEDULE (~1–4 GPU-h per clip, i.e. do-as-i-do's budget): Stage A — init from HaWoR (world hand + camera) and the existing render_and_compare framework (per-frame object poses via its mask/depth losses), least-squares spline fit, freeze poses, fit appearance; Stage B — joint optimization of splines + grasp transforms + scale, coarse-to-fine in image resolution and knot density (2→8 Hz); Stage C — unlock displacement field and a bounded per-frame residual (±1σ around the spline) to recover true high-frequency motion, reported with/without.

(5) EVALUATION on the extended HOI4D GT-depth harness (~20–30 clips): metric size/depth error, world MPJPE, chamfer/ADD vs GT-depth-unprojected reference, plus NEW temporal metrics — acceleration error (mm/s²), pose jitter (deg/frame², mm/frame²), apparent-scale constancy, contact persistence — against the 4 harness pipelines, BIGS, GHOST, and critically against each baseline + OneEuro/SmoothNet/spline post-filtering, the ablation that proves joint pixel-level optimization strictly dominates filtering (filters trade jitter for lag and cannot correct scale/depth/floating).

Key assumptions

  • Object is rigid: SE(3) trajectory + small displacement-field refinement suffices; articulated/deformable objects are out of scope (stated limitation, future work).
  • SAM-3D produces a topologically usable canonical mesh from at least one high-visibility frame, with errors correctable by the displacement field + silhouette losses (harness evidence: kettle mesh usable but −21% size / aspect-ratio bias).
  • Per-frame initializations (HaWoR hand+camera, render_and_compare object poses) land within the photometric basin of convergence (~15° / ~3 cm); coarse-to-fine rendering and the DINOv2 feature-metric loss are assumed to widen this basin enough on real clips.
  • SAM2 video segmentation with point prompts is reliable per entity (the harness already showed text prompts fail with distractor objects and point+negative prompts fix it), and mask adjacency is a good enough seed for contact-segment detection.
  • Camera intrinsics and extrinsics are available (HOI4D GT; SLAM/HaWoR in the wild) — world-frame smoothness and metric claims degrade with camera-pose error; optional camera-refinement spline mitigates but does not remove this dependency.
  • Absolute metric scale/depth requires SOME depth signal (HOI4D GT depth for the benchmark, metric monocular depth in the wild) or the hand-size prior; RGB-only operation works but with weaker metric claims.
  • Object appearance is approximately time-invariant over a clip (per-frame affine exposure absorbs lighting drift); heavy motion blur and strong specularity are handled by loss downweighting, not modeled.
  • Grasp rigidity holds within detected contact segments up to slow drift (regrasping/rolling manipulation is captured by segment splitting + the drift spline; rapid dexterous regrasps may violate this).
  • Offline budget of ~1–4 GPU-hours per clip is acceptable (matches the already-spent do-as-i-do budget); this is not a real-time method and does not claim to be.
  • Enough per-entity visual signal (texture, silhouette motion, or depth) exists to disambiguate pose; textureless rotationally-symmetric objects fall back on silhouette+depth+contact terms with expectedly weaker rotation accuracy (report symmetry-aware metrics).
  • HOI4D provides sufficient clips with GT depth + object annotations across categories (~20–30 clips) to make the extended harness statistically meaningful, and BIGS/GHOST code runs on it for direct comparison (both repos are public).

Novelty crowded not pre-empted search: verified-by-search

Category-agnostic HOI reconstruction from monocular video is a fast-moving lineage with multiple papers per cycle (HOLD CVPR'24, Get a Grip ECCV'24, G-HOP CVPR'24, BIGS CVPR'25, Hand-held Object Reconstruction CVPR'25, GHOST, Grasp-in-Gaussians, ManiSplat, HOIGS all in the 2026 preprint wave), and the Gaussian-splatting instantiation specifically has at least four 2025-26 entries.

GraG already claims temporal stability as its headline benefit, so the window for the 'per-frame poses are the problem' pitch is actively closing; however, the specific contact-factorized continuous-time parameterization and the temporal-stability benchmark are unclaimed, so it is crowded rather than saturated.

Full novelty delta

The generic framing ('MANO-rigged hand Gaussians + unknown-object Gaussians optimized end-to-end through a rendering loss') is ALREADY published — BIGS (CVPR'25) and GHOST/GraG (2026 preprints) do exactly that, so the branch cannot be sold as 'GaussianAvatar-for-HOI'.

What no found work does is the branch's actual technical core: (1) making the ENTIRE clip's geometric state continuous-time and contact-factorized — object pose defined as T_wrist(t) ∘ G_k (one latent grasp transform per contact segment + regularized drift) during grasps and a cumulative se(3) B-spline when free — so hand-relative jitter and floating are unrepresentable rather than penalized, inside a jointly rendered two-entity Gaussian objective with unknown object geometry.

Get a Grip (ECCV'24) has the hand-relative grasp constraint but only for CAD-template objects, mask-only losses, and isolated pre-annotated grasp segments; HOIGS has splines-in-GS but for full-body scenes with world-frame object poses; SplineGS-family shows splines are a commodity component.

(2) No GS-based HOI work benchmarks metric world-frame temporal stability (acceleration error, pose jitter, apparent-scale constancy, contact persistence) against GT depth, nor runs the 'baseline + OneEuro/SmoothNet post-filter' ablation the branch proposes as its central evidence.

The novelty is therefore real but narrow and mechanism-level: parameterization-as-constraint (contact factorization + continuous time) plus a temporal-stability evaluation protocol, and the paper must be written and ablated around exactly that delta against BIGS/GHOST/GraG, not around the rigged-Gaussians framing.

⚠ Failure modes

  • Core hypothesis can backfire empirically: T_obj(t) := T_wrist(t) ∘ G_k hard-wires HaWoR wrist-tracking error (jitter, drift, depth bias — worst exactly when the hand is occluded by the grasped object) directly into the object trajectory. If mask/depth-based object evidence is locally better than wrist tracking, the factorization DEGRADES object accuracy versus per-frame baselines, and the headline 'parameterization dominates losses' claim collapses. The escape hatches (drift spline, soft segment blending, Stage-C bounded per-frame residuals) each reintroduce the per-frame DOF the pitch says are unrepresentable — a sharp reviewer will call the final system 'per-frame poses with a strong spline prior', i.e., exactly the loss/filter coupling the paper attacks.
  • The photometric-tracker premise is weakest where jitter is worst: during manipulation the object is 50–80% hand-occluded, hands are near-textureless and self-similar, objects are often specular or rotationally symmetric, and typical per-frame jitter (1–3 mm / 1–2°) is sub-pixel at HOI4D viewing distances. In these null spaces of the rendering loss the parameterization suppresses jitter by PRIOR, not by pixel evidence — philosophically the same as a filter — so the central ablation (joint pixel optimization vs baseline+SmoothNet/spline post-fit) may show a small or zero accuracy delta, leaving only smoothness gains that a spline post-fit also achieves. The whole paper stands or falls on this one ablation and it has a realistic chance of coming out flat.
  • Contact-segmentation cascade: SAM2 mask adjacency + proximity is a weak grasp detector (hovering ≠ grasping; occlusion merges masks; regrasps split poorly). A wrong contact segment imposes rigid attachment on a free object (or vice versa), producing large correlated errors — a strictly worse failure mode than the baselines' independent per-frame noise, and one reviewers will probe with regrasp/handover clips.
  • Novelty is assembly-level and the field is closing fast: BIGS (CVPR'25) owns rigged-GS-for-HOI, Get a Grip (ECCV'24) owns hand-relative grasp factorization, SplineGS/HOIGS own splines-in-GS, GraG already markets jitter suppression, and CARI4D (CVPR'26, NVIDIA) claims category-agnostic METRIC-SCALE temporally consistent 4D HOI via render-and-compare + contact reasoning. The remaining delta — composing these inside one GS objective — reads as 'known ingredients, new glue' unless gains are large; that is the canonical CVPR borderline-reject profile.
  • The evaluation-protocol contribution is also eroding: acceleration-error metrics (Acc-h/Acc-o vs GT) already appear in 2026 4D-HOI papers (e.g., THO spatial-temporal transformer lineage, CARI4D), and accel error has been standard in human motion since VIBE. 'First temporal-stability benchmark for GS-based HOI with GT depth' survives, but that is a thin qualifier, not a headline claim.
  • Temporal metrics are gameable by construction and reviewers know it: a spline parameterization trivially wins jitter/accel/scale-constancy while risking lag and oversmoothing of true fast motion (regrasps, impacts). Worse, measuring mm/s² acceleration error requires per-frame GT object pose far more accurate than HOI4D's (partly interpolated, annotator-noisy) annotations provide — the evaluation may be measuring GT noise. Mocap-grade alternatives (ARCTIC, DexYCB, HO3D) have templates and template-based SOTA that would beat a SAM-3D-mesh method on raw accuracy, an unflattering comparison the paper cannot avoid being asked for.
  • Baseline reproduction risk: GHOST and GraG are preprints with unverified code availability; BIGS was evaluated under a different protocol. If these cannot be run fairly on the HOI4D GT-depth harness in world-frame metric terms, the comparison table degrades to the user's own 4 pipelines plus filters, weakening the SOTA claim.
  • Headline motivation numbers are vulnerable: the −29% to −81% depth and +33–43% size errors quoted for baselines come from methods NOT given the depth signal this method uses. The mandatory fairness ablation (baseline + same depth term + global scale correction + post-filter) may close most of the motivating gap before the proposed machinery even enters.
  • Scooping window: submission would target CVPR 2027 (Nov 2026 deadline); given 4+ GS-HOI entries in the 2026 preprint wave alone, the probability that a contact-factorized or continuous-time HOI-GS paper appears before then is substantial, and the branch has no second line of defense if the parameterization claim is taken.

⚠ Unsound assumptions

  • 'Jitter cannot exist unless it improves photometric fit in every frame' — false as stated: jitter lives in the photometric null space (occluded, textureless, symmetric, motion-blurred regions), which is precisely where per-frame methods jitter most; there the parameterization acts as a prior indistinguishable in kind from a filter.
  • Basin-of-convergence assumption (~15°/~3 cm from per-frame init) is contradicted by the branch's OWN harness evidence of −29% to −81% absolute depth error and +33–43% size error in the initializing pipelines; coarse-to-fine + DINOv2 widening the basin that far is asserted, not evidenced.
  • Grasp rigidity within mask-adjacency-detected segments: adjacency is not contact, and in-hand rotation/rolling manipulation (common in HOI4D categories like scissors, kettle pouring) violates the single-G_k-plus-slow-drift model in ways soft blending only papers over.
  • Time-invariant object appearance with per-frame GLOBAL affine exposure: the hand casts strong spatially-varying moving shadows and inter-reflections on the object during manipulation; a global affine cannot absorb this, injecting structured photometric error exactly at the contact region the method cares most about.
  • HOI4D GT object-pose annotations are accurate and temporally dense enough to score acceleration error in mm/s² — unverified and likely false for second-derivative metrics.
  • BIGS/GHOST/GraG code runs on HOI4D for direct world-frame metric comparison — GHOST and GraG are preprints; code release and protocol compatibility are unverified.
  • That matching do-as-i-do's 1–4 GPU-h budget is acceptable to reviewers when CARI4D and feed-forward competitors (THO at 31.5 FPS) are simultaneously claiming comparable temporal consistency at orders-of-magnitude lower cost — 'offline is fine' is a 2024 assumption applied to a 2027 reviewing climate.

data

MODERATE. HOI4D with GT depth exists and the team's harness already runs on it, but ~20–30 clips is a small benchmark for cross-category claims, GT pose annotation quality is likely insufficient for second-derivative (acceleration) metrics, and the mocap-grade alternatives (ARCTIC/DexYCB/HO3D) come with object templates that both undercut the 'unknown object' story and invite unflattering comparison to template-based SOTA. Problem statement

Given a single monocular RGB video (moving/egocentric camera) of a hand manipulating an unknown rigid object, recover a metrically scaled 4D reconstruction — MANO hand trajectory, model-free object shape with its SE(3) trajectory, and camera path — that is simultaneously per-frame accurate AND temporally/physically consistent: no hand-object floating, no interpenetration flicker, no relative-depth or scale drift.

All four pipelines evaluated on our HOI4D GT-depth harness (render_and_compare, do-as-i-do, ForeHOI, HORT) fail this: monocular methods mis-scale the object by +33–43% and misplace its depth by −29% to −81% (kettle clip C12/N15), and every method exhibits relative hand-object jitter that required ad-hoc temporal-smoothing patches — because they estimate frames (nearly) independently and couple hand and object only through per-frame heuristics, so monocular evidence never constrains the interaction itself.

The problem is to reformulate 4D HOI reconstruction as one full-clip test-time optimization in which temporal smoothness and contact physics are structural properties of the parametrization, not post-hoc filters — within the multi-hour per-clip budget that existing pipelines (do-as-i-do: ~3 h per 5 s clip) already spend.

Technical core

A three-layer compositional 4D Gaussian scene rendered through one differentiable rasterizer with alpha compositing, optimized jointly over the whole clip.

(1) BACKGROUND layer: static world-frame 3DGS initialized from hand/object-masked metric SLAM (DROID/MASt3R-SLAM + MoGe/UniDepth metric depth), with per-frame camera SE(3) refined SplaTAM-style; static-by-parametrization, it pins the camera trajectory and the metric scale gauge so hand-object relative-depth errors become photometrically visible misalignments (this is exactly the anchor that made render_and_compare GT-exact when GT depth was injected — here recovered, not given).

(2) HAND layer: Gaussians rigged to MANO (barycentric face attachment + LBS); free parameters are shape beta, per-Gaussian appearance/opacity/scale, and a continuous-time pose trajectory — wrist SE(3) and PCA-articulation as cubic B-splines in se(3) with knots every ~0.2 s, so the trajectory is band-limited and jitter is unrepresentable.

(3) OBJECT layer: canonical model-free Gaussians (initialized from SAM-3D/HORT lifted by clip-wide fusion, which also fills hand-occluded regions) plus a rigid SE(3) spline trajectory.

CONTACT COUPLING, the differentiator, is one reparametrization plus two Gaussian-space energies, gated by an inferred contact posterior: (a) phase detection — CHOIR dense hand-contact fields (already in the render_and_compare backend) fused with a track test (TAPIR/CoTracker tracks on the object mask are marked in-contact when their motion is rigidly explained by wrist motion over a window), segmenting the clip into free/approach/grasp/release; (b) grasp-phase reparametrization — during each grasp phase p the object trajectory becomes T_o(t) = T_wrist(t) ∘ G_p ∘ ΔT(t) with G_p one constant grasp transform and ΔT(t) an identity-regularized slack spline, structurally deleting the relative-pose DOF that produce floating/flicker while still permitting evidence-driven in-hand slip; (c) attraction — contact-labeled hand Gaussians x_i are pulled to the object iso-surface using the object Gaussian mixture density F_o(x)=Σ_k o_k N(x; μ_k, Σ_k) as a soft SDF: E_att = Σ_i (F_o(x_i) − τ)²; (d) non-penetration, symmetric — E_pen = Σ_k ReLU(−sdf_MANO(μ_k^obj))² using the exact differentiable point-to-mesh SDF of the posed watertight MANO, plus Σ_{i∉contact} ReLU(F_o(x_i) − τ)² for hand Gaussians.

Full objective: photometric L1 + D-SSIM on the composite render, per-layer SAM2/SAM3 video-mask supervision (point-prompt protocol already validated on the harness), rendered-depth vs. metric mono-depth consistency, long-range 2D track reprojection on hand and object Gaussians (disambiguates low-texture skin/plastic), E_att + E_pen, and spline acceleration priors.

Optimization schedule fitting the multi-hour budget: Stage A masked background SLAM + camera; Stage B per-frame initialization (WiLoR/HaMeR hand, HORT/SAM-3D object) fit by splines; Stage C joint photometric refinement without contact; Stage D 2–3 EM rounds — E-step re-estimate contact posteriors/phase boundaries from current geometry and tracks, M-step re-optimize with (b)–(d) — making contact inference self-correcting rather than trusted upfront.

Evaluation reuses the existing HOI4D GT-depth harness and the four adapted baselines in the common scene format: current size/depth-error metrics plus new interaction metrics (relative hand-object pose acceleration RMS, penetration depth/volume rate, contact-persistence IoU against contact derived from HOI4D GT hand+object poses) and per-frame chamfer/MPJPE to demonstrate no accuracy trade-off; ablations peel off contact terms (recovering the b2 baseline), background layer, splines, and grasp reparametrization to attribute the gains.

Key assumptions

  • The manipulated object is rigid (HOI4D-style manipulation); articulated/deformable objects are out of scope or a stated extension.
  • Contact-phase detection (CHOIR contact fields + rigid-track-correlation) is precise enough that grasp phases are correctly segmented; false-positive contact is the main risk, mitigated by soft posteriors, the identity-regularized slack spline, and EM re-estimation rather than hard upfront trust.
  • There is enough camera motion and background texture/parallax for masked metric SLAM to anchor scale and camera (true for egocentric HOI4D; degrades on static-tripod textureless scenes, where scale falls back to metric mono-depth priors).
  • Per-frame initializations (WiLoR/HaMeR hand, SAM-3D/HORT object, SAM2/SAM3 point-prompt masks — all already wired in the repo) land within the basin of convergence of the joint photometric refinement.
  • Accumulating object observations across the clip provides enough angular coverage to fuse a usable canonical Gaussian shape despite persistent hand occlusion.
  • Relative hand-object jitter, floating, and penetration flicker are the dominant residual failure mode (supported by the harness: +33-43% size / -29-81% depth errors for monocular baselines, plus the documented temporal-smoothing and scale-fix patches), and reviewers will accept new temporal/contact metrics alongside standard per-frame ones.
  • A multi-hour offline per-clip budget is acceptable to the community for this problem (precedent: do-as-i-do already spends ~3 h on a 5 s clip; HOLD-style per-clip optimization is an accepted paradigm).
  • Photometric splatting loss is informative on low-texture skin and objects once combined with mask and long-track losses; motion blur and specularities are handled by robust losses rather than breaking convergence.
  • GT contact for the contact-persistence metric can be derived from HOI4D's GT hand and object pose annotations (proximity thresholding), since HOI4D ships GT depth and poses but not explicit contact labels.

Novelty crowded not pre-empted search: verified-by-search

Monocular hand-object reconstruction with Gaussian splatting has become one of the hottest micro-niches of 2025-2026: at least eight directly overlapping papers appeared in the last ~14 months (BIGS CVPR'25, Interaction-Aware 4DGS 11/25, Grasp-and-Lift 1/26, AGILE 2/26, GHOST 3/26, GraG 4/26, DP-DeGauss 4/26, CHOIR 5/26, Clay-to-Stone CVPR'26 Highlight), and two of them (GHOST, CHOIR) already claim contact-aware/physically-consistent monocular HOI.

The exact intersection proposed (background-anchored metric scale + structural grasp coupling + contact energies in one 4DGS optimization) is still unclaimed, so it is 'crowded' rather than 'saturated' — but the window is closing fast and concurrent-work collisions by a CVPR 2027 deadline are likely.

Closest published work

  • CHOIR: Contact-aware 4D Hand-Object Interaction Reconstruction arXiv, May 2026
    Closest conceptual overlap: monocular open-world video, model-free object shape + 6D pose over time, and contact used as an explicit hand-object coupling signal via contact-aware joint optimization with dynamically updated contact constraints (essentially the branch's EM-style contact re-estimation idea). It validates the branch's core hypothesis but also preempts much of it; it does not appear to use Gaussian splatting as the optimization substrate, nor a static-background layer for metric-scale/camera anchoring, nor a grasp-transform trajectory reparametrization.
  • GHOST: Fast Category-agnostic Hand-Object Interaction Reconstruction from RGB Videos using Gaussian Splatting arXiv, Mar 2026
    Monocular RGB video, Gaussian (2DGS disc) hands+objects, category-agnostic, with grasp-aware alignment refining hand pose and OBJECT SCALE for physically consistent contact, plus hand-aware occlusion-robust losses; evaluated on ARCTIC/HO3D/in-the-wild. Directly contests the claim of 'first physically consistent contact inside a GS pipeline', though its contact handling is an alignment step rather than continuous contact/non-penetration energies in a whole-clip joint optimization, and it has no SLAM-anchored metric background layer.
  • Interaction-Aware 4D Gaussian Splatting for Dynamic Hand-Object Interaction Reconstruction arXiv, Nov 2025 (rev. Jun 2026)
    Monocular 4DGS for HOI without object priors: interaction-aware hand-object Gaussians with occlusion/edge parameters, hand-conditioned object deformation fields, physical-interaction and smooth-motion regularizers, and progressive dynamic-vs-static-background handling.   • Clay-to-Stone: Phase-wise 3D Gaussian Splatting for Monocular Articulated Hand-Object Manipulation Modeling CVPR 2026 (Highlight)
    Monocular GS-based hand-object manipulation with a phase-structured optimization (flexible CLAY phase then rigidity-enforcing STONE phase) — publishes the 'phase-wise structure inside GS optimization' pattern the branch uses for grasp phases, though aimed at articulated objects and without contact energies or background/scale anchoring. Code: https://github.com/ru1ven/ARGS.
  • BIGS: Bimanual Category-agnostic Interaction Reconstruction from Monocular Videos via 3D Gaussian Splatting CVPR 2025
    Monocular HOI 3DGS with MANO-prior hand Gaussians, model-free object Gaussians completed via SDS diffusion prior, and an interacting-subjects joint alignment step. Establishes the MANO-rigged-GS + model-free-object-GS composition; no explicit contact/non-penetration energies, background layer, metric scale, or trajectory splines.
  • Grasp-and-Lift: Executable 3D Hand-Object Interaction Reconstruction via Physics-in-the-Loop Optimization arXiv, Jan 2026
    Occupies the 'interaction physics as the differentiator' position via a stronger mechanism: simulation-in-the-loop where the wrist is welded to a kinematic control body and the object's motion is computed from contact forces, with cubic-spline low-jerk trajectories. Functionally supersedes the branch's grasp-transform reparametrization + contact energies for physical plausibility, though it is mesh/simulator-based, not a differentiable-rendering GS scene with background.
  • DP-DeGauss: Dynamic Probabilistic Gaussian Decomposition for Egocentric 4D Scene Reconstruction arXiv, Apr 2026
    Egocentric 4DGS that probabilistically routes a unified Gaussian set into background / hand / object branches with category masks — publishes the three-layer compositional background+hand+object GS scene decomposition itself, without MANO rigging, contact physics, or metric-scale claims.
  • Grasp in Gaussians (GraG): Fast Monocular Reconstruction of Dynamic Hand-Object Interactions arXiv, Apr 2026
    Monocular dynamic HOI with a compact sum-of-Gaussians representation, SAM3D-video object initialization (same init the branch plans), joint/depth alignment losses, 6.4x faster tracking. Overlaps the pipeline plumbing and the dynamic-HOI-in-Gaussians framing; no contact energies or background anchoring.
  • HOLD: Category-agnostic 3D Reconstruction of Interacting Hands and Objects from Video CVPR 2024
    The acknowledged baseline paradigm: per-clip optimization of hand + model-free object from monocular video, already including a contact loss favoring physically plausible hand-object constellations — so 'contact in the per-clip HOI optimization' per se dates to 2024; the branch's delta must rest on the GS substrate, structural (not penalty-only) coupling, and scale/background anchoring.
  • HaWoR: World-Space Hand Motion Reconstruction from Egocentric Videos CVPR 2025
    Covers the background-anchoring ingredient: adaptive SLAM for egocentric video fused with a metric depth foundation model to recover metrically scaled world-space hand trajectories — the branch's Stage-A (masked metric SLAM anchoring camera + scale) is essentially this, extended to objects.
  • MANUS: Markerless Grasp Capture using Articulated 3D Gaussians CVPR 2024
    Contact estimation via articulated hand Gaussians and object Gaussians (Gaussian-space proximity), but in a dense multi-view rig with known setup — the branch correctly cites it; it defines contact-in-Gaussian-space but not as an optimization constraint in a monocular setting.

Full novelty delta

Not already done as a whole, but the headline claim needs rewriting.

Every individual ingredient is now published: contact-as-coupling-signal joint optimization on monocular video (CHOIR '26, HOLD '24), grasp-aware contact alignment inside a monocular GS pipeline (GHOST '26), phase-structured GS optimization for manipulation (Clay-to-Stone CVPR'26 Highlight), MANO-rigged + model-free-object Gaussians (BIGS CVPR'25), background/hand/object compositional egocentric GS (DP-DeGauss '26, Interaction-Aware 4DGS '25), SLAM+metric-depth world anchoring (HaWoR CVPR'25), and simulator-grade interaction physics with wrist-welded object motion and spline trajectories (Grasp-and-Lift '26).

The surviving delta is the specific constraint STRUCTURE and the metrology: (1) a metric SLAM-anchored static-background GS layer that turns hand-object relative-depth/scale errors into photometric residuals — absent from all HOI-GS works, which drop the background and leave scale unanchored (the +33-43% size errors the harness documents); (2) grasp-phase kinematic reparametrization T_o=T_wrist∘G_p∘ΔT plus band-limited se(3) splines, making jitter and floating unrepresentable by construction rather than penalized (GHOST/CHOIR/HOLD all use soft losses or one-shot alignment; Clay-to-Stone's phases target articulation rigidity, not hand-object coupling); (3) Gaussian-mixture-density attraction + posed-MANO-SDF non-penetration as energies inside the whole-clip splatting objective with EM contact re-estimation; and (4) an evaluation contribution: GT-depth harness with 4 reproduced baselines and new relative-jitter/penetration/contact-persistence metrics.

To be defensible at CVPR the paper must position against and empirically beat GHOST, CHOIR, and BIGS (not just HOLD/MANUS), and the claim should be 'structural contact coupling + background-anchored metric scale in compositional 4DGS', not 'first contact in splatting'.

⚠ Failure modes

  • Concurrent-work collision is near-certain, not hypothetical: 8+ monocular HOI-GS papers in 14 months, two of which (GHOST 3/26, CHOIR 5/26) already claim contact-aware/physically-consistent monocular HOI, and Clay-to-Stone (CVPR'26 Highlight) already published phase-structured GS optimization for manipulation. By a Nov 2026 CVPR'27 deadline the surviving delta ('constraint structure + background scale anchor') will read to reviewers as a recombination of published ingredients, and 1-2 more collisions in the interim are likely.
  • The grasp weld T_o = T_wrist ∘ G_p ∘ ΔT structurally propagates hand errors into the object — the exact bug this team already diagnosed in its own harness: do-as-i-do's hand-anchored depth inherited HaWoR's +28% hand-depth error until they replaced it with a GT anchor. Monocular wrist SE(3) (WiLoR/HaMeR) is depth-ambiguous and jittery; welding the object to it trades hand-object relative jitter for correlated absolute error, and the joint optimization must fix the hand and object simultaneously for the weld to help — a circular dependency the proposal never resolves.
  • EM contact-phase estimation over discrete grasp boundaries inside a nonconvex photometric landscape is fragile: a mis-detected grasp onset welds the object to the wrist during approach (object drags/teleports), and once the M-step has satisfied the weld photometrically, the E-step has little gradient signal to undo it. Soft posteriors + slack splines mitigate but also reintroduce the very relative-pose DOF the reparametrization claims to delete — the method's headline ('jitter unrepresentable by construction') and its escape hatch (identity-regularized ΔT(t) slack) are in direct tension.
  • The claim that a background GS layer makes relative-depth errors 'photometrically visible' is optically weak: depth errors along the optical axis are precisely what photometric losses are least sensitive to under the small parallax of a 5 s handheld clip. The real depth signal is the rendered-depth vs. metric-monodepth loss — which any baseline could bolt on — so the ablation must disentangle 'contact structure' gains from plain depth supervision, and reviewers will suspect the latter explains most of the scale/depth improvement.
  • Self-serving evaluation circularity: the proposed new metrics (relative pose acceleration RMS, penetration rate, contact-persistence IoU) are exactly the quantities the method's constraints enforce by construction. A trivially wrist-welded object scores perfectly on all three while being geometrically wrong. Unless the method also wins (not just ties) on independent per-frame chamfer/MPJPE/ADD, an AC will read the metric suite as designed for the method.
  • The Gaussian-mixture density F_o(x) as a soft SDF has a known degenerate solution: the optimizer can satisfy E_att and E_pen by shrinking opacities/scales of Gaussians near the contact region instead of moving geometry, since o_k, Σ_k are co-optimized with μ_k. This requires detach schedules and per-term LR surgery — exactly the fragile-hyperparameter territory that kills reproducibility and rebuttals.
  • The motivating evidence is n=1: the entire quantitative case (+33-43% size, −29 to −81% depth) comes from ONE 5-second kettle clip (compare/hoi4d/depth_eval.md), and the 'jitter is dominant' claim from one commit-level flicker fix — which, tellingly, a cheap temporal depth-smoothing patch already fixed. If a 10-line smoothing filter removes the perceptual artifact, demonstrating that hours of structural contact machinery buys a visible margin over 'baseline + smoothing + monodepth loss' is a genuinely hard experimental bar.
  • Baseline reproduction gap: to be defensible the paper must beat GHOST, CHOIR, and BIGS, but GHOST and CHOIR are 2026 arXiv works with uncertain code release; comparing only against HOLD/HORT/ForeHOI (what the harness has) invites a one-line rejection for missing the closest published baselines, and re-implementing either is a multi-month project by itself.
  • Benchmark scale-up cost: a credible CVPR paper needs ~30-50 HOI4D clips plus HO3D/ARCTIC or in-the-wild results for comparability; at multi-hour whole-clip optimization × (method + 5 ablations) this is hundreds of GPU-hours of turnaround per experimental iteration, which slows the debug loop of an already fragile multi-stage system (masked SLAM → per-frame init → joint photometric → EM contact) where any stage failing sinks the clip.
  • Paradigm-timing risk: the field is visibly moving feed-forward (HORT ~1 min, GraG advertises 6.4x faster tracking); a multi-hour per-clip test-time optimization pitched at CVPR 2027 continues a 2024 paradigm (HOLD) and will draw 'expensive per-scene optimization, limited practical relevance' reviews unless the accuracy gap over fast methods is dramatic.

⚠ Unsound assumptions

  • 'Relative hand-object jitter is the perceptually and metrically dominant failure mode' — the harness actually documents SCALE and DEPTH errors as dominant (addressed by the background/depth anchor, not by contact coupling); the jitter evidence is one flicker anecdote already fixed by trivial temporal smoothing, so the differentiating machinery targets the weaker-evidenced failure.
  • 'Per-frame initializations land within the basin of convergence of joint photometric refinement' — contradicted by the harness itself: HORT places the object at −81% depth; nothing photometric recovers from that, so convergence actually rests on the depth/track losses being strong enough to move the object ~0.7 m, which is asserted, not shown.
  • 'Background GS layer turns relative-depth/scale errors into photometric residuals' — under 5 s of handheld parallax, along-axis depth errors are nearly photometrically invisible; the anchor that was 'GT-exact' in render_and_compare used injected GT depth, and replacing GT depth with SLAM+monodepth (5-15% metric error typical) does not license extrapolating that exactness.
  • 'Reviewers will accept new temporal/contact metrics alongside standard ones' — risky when the new metrics are optimized by construction; acceptance hinges on winning independent metrics, which the proposal only promises to 'not trade off'.
  • 'GT contact can be derived from HOI4D GT poses by proximity thresholding' — HOI4D object-pose annotations have documented noise at the centimeter level, comparable to the contact threshold itself, so the contact-persistence GT is itself uncertain in exactly the regime being measured.
  • 'Soft posteriors + EM make contact inference self-correcting' — EM over discrete phase boundaries with a photometric M-step has no guarantee of escaping a wrong initial segmentation; CHOIR's dynamically-updated contact constraints already occupy this idea, so it is both fragile and non-novel.
  • 'Clip-wide fusion provides enough angular coverage for canonical object shape' — HOI4D manipulations are short and one-sided; the object back face is often never observed, forcing a diffusion/SDS completion prior (as BIGS needed), which the technical core omits.

Feasibility

data

Good raw availability, thin current state. HOI4D (GT depth + poses) is in hand and partially wired, SAM2/SAM3 mask protocol validated, four baselines adapted — but the harness today is ONE kettle clip (compare/hoi4d/depth_eval.md). Scaling to 30-50 rigid-object clips across categories plus an external benchmark (HO3D/ARCTIC for comparability with GHOST/BIGS numbers) is mandatory and is weeks of curation; GT contact labels must be synthesized from noisy pose annotations. Rigid-only scope excludes several HOI4D categories.

compute

Acceptable but painful. Single-GPU per clip is fine; the problem is iteration velocity: whole-clip 4DGS + per-iteration posed-MANO SDF + spline optimization + 2-3 EM rounds plausibly lands at 2-6 h/clip, and a full result table (method + 5 ablations + 4 baselines × ~30-50 clips) is 500-1500 GPU-hours per experimental sweep. On rented GPUs this is affordable in money but expensive in debug-loop latency for a system with 4 sequential fragile stages.

evaluation

The weakest leg. (1) Closest baselines GHOST/CHOIR/BIGS likely lack usable code; without beating them head-to-head the novelty delta collapses to unverifiable prose. (2) The three new interaction metrics are enforced by the method's own constraints — circular unless per-frame chamfer/MPJPE/ADD also improve, which the mechanism gives no strong reason to expect. (3) The most damaging ablation ('baseline + temporal smoothing + monodepth loss', i.e., the cheap fixes already applied in this repo) is exactly the one reviewers will demand and the one the structural machinery may fail to clearly beat.

Verdict: maybe — As specified, this is a 2026-vintage recombination entering the single most crowded micro-niche in the area, with its headline mechanism (contact coupling) targeting the weaker-evidenced failure mode (n=1 flicker anecdote already fixed by cheap smoothing) while its stronger-evidenced problem (metric scale/depth, +33-43%/−81% on one clip) is addressed by an ingredient (SLAM+monodepth background anchoring) that is closest to a bolt-on depth loss any baseline could adopt. It escapes 'drop' only because two assets are real and rare: a GT-depth harness with four reproduced baselines (currently n=1 clip — must become n≈40 before anything else), and the genuinely unclaimed metric-background-anchored composition. Pursue only under a hard repositioning: lead with the benchmark/metrology contribution plus background-anchored metric scale, demote contact energies to one ablated component, budget for reproducing or numerically matching GHOST/CHOIR/BIGS, and pre-register the killer ablation (baseline + smoothing + monodepth loss) — if that ablation closes most of the gap in a 2-3 week pilot on ~10 clips, drop the branch.

Why this direction 
**Why this branch.** Three reasons, in order of weight:

1. **It attacks the failure the harness actually proved, with the mechanism the harness actually validated.** The controlled experiments are unambiguous: GT-depth injection makes the *unchanged* pipelines essentially exact (0% object depth/size error for render_and_compare); a better depth net changes nothing; filtering fixes only the high-frequency band. That is a measured statement that the per-frame metric gauge — not pose estimation, not contact modeling — dominates the error. b1-b3 all spend their machinery on pose/contact coupling and each carries a known-unsound mechanism (b1's dynamic-object depth triangulation does not exist in principle; b2/b3's grasp weld imports the HaWoR error this team already diagnosed and reverted). b6 is the only branch whose core mechanism is *already demonstrated* in-repo, just with GT depth standing in for the substrate.

2. **It is the most feasible and the most falsifiable.** Feasibility 7.5 — highest of all six. GS-BA is 10-40 min/clip vs hours for b1-b3; injection interfaces exist and are proven (`real_perception.py` sensor-depth path, `--gt-anchor`); and — uniquely — the load-bearing assumption (background-fitted affine gauge corrects hand/object-region depth) is **checkable per-pixel against HOI4D GT depth in the first week, before building anything**. # 4D Gaussian Splatting as the Temporal-Consistency Backbone for Monocular HOI Reconstruction — Final Ideation Report

## Original idea

All four HOI pipelines tested on the HOI4D GT-depth harness (render_and_compare, do-as-i-do, ForeHOI, HORT) share the same structural failure: per-frame, weakly-coupled monocular estimation produces jitter and floating — HaWoR hand-depth wiggle ratio 7.9, hand-object depth correlation 0.775, 1.75x apparent-size flicker of a rigid object, HORT z-teleports of ~1.15 m. Since a multi-hour per-clip budget is already being spent (do-as-i-do: ~3 h per 5 s clip), the researcher proposes re-spending it on a **dynamic Gaussian Splatting reconstruction whose joint multi-frame photometric optimization makes MANO hand and unknown-object (SE(3) + model-free mesh) trajectories temporally smooth by construction**, matching accuracy on the existing GT-depth harness. Candidate instantiations: GS-as-scaffold (reconstruct then fit templates), template-embedded Gaussians, contact-coupled compositional GS, and GS as pseudo-GT for distilling stable feed-forward models. Target: CVPR/ICLR/CoRL/NeurIPS, on 2x RTX 4090 with existing assets (HaWoR, SAM3/SAM-3D, MoGe/DA3, TAPIR, render_and_compare, HOI4D harness).

Two harness findings anchor everything downstream: (1) **swapping the depth backbone (MoGe → DA3-metric) changes nothing** (1.75x → 1.76x flicker) — the error enters through the anchoring structure, not the estimator; (2) **output filtering fixes only the high-frequency band** (flicker 0.018 → 0.005) while the low-frequency depth swing survives (1.75x → 1.59x) — and injecting GT depth into the *unchanged* pipelines makes object depth/size essentially exact. The problem is the per-frame metric gauge, not (primarily) the pose estimators.

### b1 — 4DGS-first: reconstruct-then-parse (GS as temporal denoiser, templates extracted afterwards) — **4.5/10, maybe**

- **Idea/angle.** Two-stage decoupling: build a template-free, MoSca-style persistent-Gaussian motion field first (sparse SE(3) scaffold, DQB skinning, node trajectories in a **cubic-B-spline low-rank basis with 0.25-0.4 s knots** so frame-rate jitter is *unrepresentable*), then extract templates post-hoc: object SE(3) per frame via **closed-form weighted Umeyama/Procrustes** on persistent Gaussian correspondences (IRLS/Huber), MANO via one canonical-frame binding + per-frame trajectory IK with **no temporal smoothness term** (the headline ablation).
- **Novelty delta.** No published work makes a band-limited template-free Gaussian field the *sole* 3D evidence with post-hoc template registration. But GraG (arXiv 2604.12929, Apr 2026, https://arxiv.org/abs/2604.12929) already owns "temporally stable, template-light Gaussian HOI tracking" (smoothness as *penalties* during per-frame SoG tracking); Interaction-Aware 4DGS (https://arxiv.org/abs/2511.14540) already does template-free 4DGS on HOI4D (but never parses templates); MoSca (https://arxiv.org/abs/2405.17421) supplies Stage 1 nearly wholesale. Stage 1 makes apparent size consistent nearly trivially while absolute depth stays pinned to the biased DA3 affine — consistency without correctness. (2) Missing killer ablation: band-limited **template-space** bundle adjustment with the same losses may tie, making the Gaussian intermediate unnecessary machinery. (3) Spline basis vs acceleration penalty (the delta vs GraG) may be empirically indistinguishable. ## Practical pipeline

**Target venue & deadline-class.** CVPR 2027 (deadline ~Nov 2026; ~4.5 months) as a 3D-vision analysis + systems paper. Fallback: ICCV/3DV. CoRL only if a retargeting-to-robot downstream result is added via the do-as-i-do stack. Not ICLR (no learning contribution).

**Datasets/benchmarks.**
- **HOI4D** rigid categories (kettle, bottle, mug, toy car): scale the existing GT-depth harness from 1 kettle clip to **20-50 clips** with GT align_depth + object pose + MANO — this scale-up is itself a deliverable and must happen first regardless of branch.
- Second RGB-D HOI dataset for external validity: **DexYCB or H2O** (GT motion for non-circular acceleration metrics).
- **wild6** clips for qualitative in-the-wild results (MASt3R-SLAM/MegaSAM cameras).

**Baselines / comparison conditions.**
- The 4 pipelines raw (render_and_compare, do-as-i-do, ForeHOI, HORT).
- Each + **oracle-tuned output filtering** (OneEuro, median+MA, spline, Kalman) — the decisive cheap-fix control.
- Each + **commodity substrates**: ViPE, MegaSaM, Video-Depth-Anything, COLMAP+MVS, per-frame depth + temporal filtering — fed through the *identical* injection interfaces (the make-or-break ablation).
- Each + **GS-BA substrate** (the method).
- Each + **GT align_depth** (the oracle ceiling).

**Method components & how to build each.**
1. *Priors:* reuse SAM2/SAM3 point-prompt masks (protocol already validated — text prompts grab wrong instances), MoGe-2/DA3-metric depth, GeoCalib gravity. All wired in-repo.
2. *Static-scene GS-BA:* gsplat-based; optimize {background Gaussians, per-frame T_t ∈ SE(3), global scale s, per-frame (a_t, b_t)} under mask-gated L1+D-SSIM on background pixels + λ|D_GS,t − (a_t·D_mono,t + b_t)| on co-visible static pixels + gravity alignment + shrinkage of (a_t,b_t)→(1,0) + camera smoothness. Static-camera clips degrade gracefully to multi-frame depth consensus. Optional: object-at-rest support-plane contact to pin s.
3. *Gauge transfer:* apply D~_t to all pixels; render amodal support depth + opacity/residual reliability maps.
4. *Injection:* 16-bit metric depth + K through `real_perception.py`'s sensor-depth path (render_and_compare); `--gt-anchor` pointmap + grasp-preserving common-delta (do-as-i-do); closed-form per-frame translation + one global scale aligning predicted points to D~_t inside their own masks (HORT/ForeHOI).
5. *Metrology:* formalize the repo's diagnostics into a stability suite (below).

**Key experiments + ablations (in execution order — the first two are gates).**
1. **Gate 1 (week 1, before any GS code):** on ≥10 HOI4D clips, fit (a_t, b_t) on background pixels against the mono-depth prior and verify per-pixel on GT align_depth that the correction reduces *hand/object-region* depth error. If affine transfer fails → drop the branch (cost: ~2 weeks).
2. **Gate 2 (weeks 2-3):** ViPE/MegaSaM/VDA through the same interfaces on the same clips. If commodity matches GS-BA → keep the substrate as infrastructure, pivot the paper to the decomposition/benchmark and reinforce b5.
3. **Oracle sandwich** (headline table): 4 methods × {mono, +substrate, +GT} × 20-50 clips; report fraction of oracle gap closed per metric, plus the gauge/pose/shape error decomposition (oracle residuals — SAM-3D −21% shape, HaWoR wobble — quantify the non-gauge components).
4. **Cheap-fix control:** oracle-tuned filters must NOT match the substrate on accuracy (they will match on some stability metrics — say so).
5. **Component ablations:** affine vs scale-only vs shift-only gauge; with/without amodal support depth; with/without gravity; static-camera subset; support-plane scale pinning on/off; anchor-flip on/off for do-as-i-do.
6. **Robustness reporting:** per-clip success rates, mask-leakage cases (the SAM3 wrong-kettle failure is already documented — feature it), frames where hands+object dominate.
7. *Compute pruning:* run do-as-i-do (~3 h/clip) on a 10-clip subset only, disclosed; full matrix on the three cheaper pipelines.

**Evaluation metrics.**
- *Accuracy:* object size error, absolute depth error, center error, ADD-S/Chamfer, hand MPJPE/MRRPE.
- *Stability:* apparent-size flicker and low-frequency swing (the two-band decomposition — keep this analysis, it is the paper's sharpest tool), depth wiggle ratio (z-path/net-displacement), acceleration jitter, hand-object depth-anchor correlation, grasp consistency. Always paired with accuracy to defuse the "smoothing wins stability for free" attack.

**Milestone timeline (to ~Nov 2026).**
- **Weeks 1-3:** Gates 1 & 2 (kill/pivot decision). In parallel: scale harness to 20 HOI4D clips.
- **Weeks 4-7:** GS-BA implementation + gauge transfer + injection into render_and_compare and HORT/ForeHOI; first oracle-sandwich slice on 10 clips.
