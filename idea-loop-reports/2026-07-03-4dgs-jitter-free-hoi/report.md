# 4D Gaussian Splatting as the Temporal-Consistency Backbone for Monocular HOI Reconstruction — Final Ideation Report

## Original idea

All four HOI pipelines tested on the HOI4D GT-depth harness (render_and_compare, do-as-i-do, ForeHOI, HORT) share the same structural failure: per-frame, weakly-coupled monocular estimation produces jitter and floating — HaWoR hand-depth wiggle ratio 7.9, hand-object depth correlation 0.775, 1.75x apparent-size flicker of a rigid object, HORT z-teleports of ~1.15 m. Since a multi-hour per-clip budget is already being spent (do-as-i-do: ~3 h per 5 s clip), the researcher proposes re-spending it on a **dynamic Gaussian Splatting reconstruction whose joint multi-frame photometric optimization makes MANO hand and unknown-object (SE(3) + model-free mesh) trajectories temporally smooth by construction**, matching accuracy on the existing GT-depth harness. Candidate instantiations: GS-as-scaffold (reconstruct then fit templates), template-embedded Gaussians, contact-coupled compositional GS, and GS as pseudo-GT for distilling stable feed-forward models. Target: CVPR/ICLR/CoRL/NeurIPS, on 2x RTX 4090 with existing assets (HaWoR, SAM3/SAM-3D, MoGe/DA3, TAPIR, render_and_compare, HOI4D harness).

Two harness findings anchor everything downstream: (1) **swapping the depth backbone (MoGe → DA3-metric) changes nothing** (1.75x → 1.76x flicker) — the error enters through the anchoring structure, not the estimator; (2) **output filtering fixes only the high-frequency band** (flicker 0.018 → 0.005) while the low-frequency depth swing survives (1.75x → 1.59x) — and injecting GT depth into the *unchanged* pipelines makes object depth/size essentially exact. The problem is the per-frame metric gauge, not (primarily) the pose estimators.

## All branches (do not lose these)

### b1 — 4DGS-first: reconstruct-then-parse (GS as temporal denoiser, templates extracted afterwards) — **4.5/10, maybe**

- **Idea/angle.** Two-stage decoupling: build a template-free, MoSca-style persistent-Gaussian motion field first (sparse SE(3) scaffold, DQB skinning, node trajectories in a **cubic-B-spline low-rank basis with 0.25-0.4 s knots** so frame-rate jitter is *unrepresentable*), then extract templates post-hoc: object SE(3) per frame via **closed-form weighted Umeyama/Procrustes** on persistent Gaussian correspondences (IRLS/Huber), MANO via one canonical-frame binding + per-frame trajectory IK with **no temporal smoothness term** (the headline ablation).
- **Novelty delta.** No published work makes a band-limited template-free Gaussian field the *sole* 3D evidence with post-hoc template registration. But GraG (arXiv 2604.12929, Apr 2026, https://arxiv.org/abs/2604.12929) already owns "temporally stable, template-light Gaussian HOI tracking" (smoothness as *penalties* during per-frame SoG tracking); Interaction-Aware 4DGS (https://arxiv.org/abs/2511.14540) already does template-free 4DGS on HOI4D (but never parses templates); MoSca (https://arxiv.org/abs/2405.17421) supplies Stage 1 nearly wholesale. Surviving delta = evidence-side band-limiting vs track-with-penalties, plus the oracle-filter benchmark.
- **Closest prior.** GraG; Interaction-Aware 4DGS; BIGS (CVPR'25, https://arxiv.org/abs/2504.09097); HOLD (CVPR'24, https://arxiv.org/abs/2311.18448); CHOIR (https://arxiv.org/abs/2605.20992); Dyn-HaMR (https://arxiv.org/abs/2412.12861). **Crowdedness: crowded.**
- **Top risks.** (1) **Likely-fatal mechanism flaw:** monocular photometric consistency cannot triangulate absolute depth for a *dynamic* rigid object — size/depth/translation scale together re-explain all images; ego-motion parallax anchors only the static background. Stage 1 makes apparent size consistent nearly trivially while absolute depth stays pinned to the biased DA3 affine — consistency without correctness. (2) Missing killer ablation: band-limited **template-space** bundle adjustment with the same losses may tie, making the Gaussian intermediate unnecessary machinery. (3) Spline basis vs acceleration penalty (the delta vs GraG) may be empirically indistinguishable. (4) MoSca-class brittleness on blurred, texture-poor, occlusion-heavy HOI footage; support-set churn at contact boundaries reinjects jitter into Procrustes/IK.
- **Scores.** novelty 5, feasibility 5.5, crowd-inv 2.5, venue-fit 6, **overall 4.5**. **Verdict: maybe** — 2-3 week kill-test first: (a) does Stage 1 reduce *absolute* object depth error vs sequence-affine DA3 on GT depth? (b) does template-space band-limited BA lose to the Gaussian pipeline? Pursue only if both go the right way.

### b2 — Template-embedded HOI Gaussians (contact-factorized continuous-time trajectories inside the rendering loss) — **4.5/10, maybe**

- **Idea/angle.** Analysis-by-synthesis where the only geometric unknowns are template trajectories: MANO with per-joint **cumulative B-spline** rotations, SAM-3D canonical object mesh (+ displacement field) with face-anchored Gaussians; the key mechanism is the **contact-factorized object trajectory** — during grasp segment k, T_obj(t) := T_wrist(t) ∘ G_k (one latent grasp transform + heavily-regularized drift spline); se(3) spline when free. Hand-relative jitter/floating is unrepresentable, not penalized. Losses: masked L1+D-SSIM, silhouette, DINOv2 feature-metric, depth, robust 2D keypoints, SDF penetration, spline acceleration.
- **Novelty delta.** The generic "GaussianAvatar-for-HOI" framing is **already published** (BIGS CVPR'25; GHOST arXiv 2603.18912; GraG). Unclaimed: whole-clip continuous-time contact-factorized state inside a jointly rendered two-entity GS objective with unknown geometry, plus a GT-depth temporal-stability protocol. Get a Grip (ECCV'24, https://arxiv.org/abs/2312.15719) has the hand-relative grasp constraint but CAD templates only, mask losses, annotated segments; HOIGS (https://arxiv.org/html/2604.04016v1) has splines-in-GS but full-body/world-frame; SplineGS (https://arxiv.org/pdf/2412.09982) makes splines a commodity component.
- **Crowdedness: crowded.** GraG already markets jitter suppression; CARI4D (CVPR'26) claims metric-scale temporally-consistent category-agnostic 4D HOI.
- **Top risks.** (1) The weld imports HaWoR wrist error into the object — the exact bug this team already diagnosed in do-as-i-do; escape hatches (drift spline, per-frame residuals) reintroduce the DOF the pitch calls unrepresentable. (2) Photometric signal is weakest exactly where jitter is worst (50-80% occlusion, textureless skin, sub-pixel jitter) — the parameterization then acts as a prior, philosophically the same as a filter; the one make-or-break ablation (joint pixel-level spline optimization vs per-frame + SmoothNet/spline post-fit, with fair depth access) has a realistic chance of coming out flat. (3) Contact-segmentation cascade errors are correlated and worse than per-frame noise. (4) HOI4D GT pose annotations likely too noisy for mm/s² acceleration metrics.
- **Scores.** novelty 4.5, feasibility 6.5, crowd-inv 2.5, venue-fit 6, **overall 4.5**. **Verdict: maybe** — 1-week 2-3-clip pilot of Stage A→C vs per-frame+SmoothNet; pursue only on a clear accuracy+stability margin, else pivot to the benchmark contribution.

### b3 — Contact-coupled compositional 4DGS (background + hand + object + contact energies) — **4.0/10, maybe (weakest)**

- **Idea/angle.** Three-layer compositional scene: static background GS (masked metric SLAM anchors camera + scale), MANO-rigged hand layer with se(3)/PCA splines, model-free object layer; **contact posterior gating** a grasp reparametrization T_o = T_wrist ∘ G_p ∘ ΔT, Gaussian-mixture-density attraction E_att, posed-MANO-SDF non-penetration E_pen, refined by 2-3 EM rounds over contact phases.
- **Novelty delta.** Every ingredient is now published: CHOIR '26 (contact-aware joint optimization with dynamically updated constraints, https://arxiv.org/abs/2605.20992), GHOST '26 (grasp-aware alignment in GS, https://arxiv.org/abs/2603.18912), Clay-to-Stone (CVPR'26 Highlight — phase-wise GS optimization), BIGS, DP-DeGauss (https://arxiv.org/abs/2604.07986 — background/hand/object GS decomposition), HaWoR (SLAM+metric-depth anchoring), Grasp-and-Lift (https://arxiv.org/html/2601.18121v1 — simulator-grade physics supersedes contact energies). Surviving delta: metric SLAM-anchored background layer + structural grasp coupling + the metrology — but "first contact in splatting" is dead.
- **Crowdedness: crowded — the single most crowded micro-niche** (8+ directly overlapping papers in ~14 months).
- **Top risks.** (1) Contact machinery targets the weaker-evidenced failure (the flicker anecdote a 10-line smoothing patch already fixed), while the stronger-evidenced failure (scale/depth) is addressed by an ingredient closest to a bolt-on depth loss. (2) Grasp weld propagates hand error (same as b2). (3) New metrics (relative accel RMS, penetration rate, contact-persistence IoU) are optimized by construction — circular unless independent per-frame metrics also win. (4) GHOST/CHOIR/BIGS reproduction needed but code availability uncertain. (5) F_o soft-SDF has a degenerate opacity-shrinking solution requiring fragile detach schedules.
- **Scores.** novelty 4, feasibility 5.5, crowd-inv 2, venue-fit 5, **overall 4.0**. **Verdict: maybe** — only under hard repositioning (lead with benchmark + background-anchored scale, demote contact to an ablated component); pre-register the killer ablation (baseline + smoothing + monodepth loss) and drop if it closes the gap.

### b4 — 4DGS as pseudo-GT data engine → distilled feed-forward student — **4.5/10, maybe (gated)**

- **Idea/angle.** Run the winning b1-b3 teacher over HOI4D-as-unlabeled + Ego4D + wild clips; automatic QA gates (rendered-mask IoU, held-out-frame renders, physics sanity); distill into a windowed video HOI transformer with **derivative-level losses** (analytic spline velocities/accelerations), a hand-frame relative-pose consistency loss, and contact BCE; headline plots = stability retention at 100-1000x speedup and corpus-scaling curves. Claim: HOI temporal stability is a property of *supervision*, not architecture or test-time optimization.
- **Novelty delta.** No work distills jointly-optimized 4D HOI reconstructions with derivative supervision into a feed-forward reconstructor. But **EgoInfinity** (arXiv 2606.17385, Jun 2026, https://arxiv.org/abs/2606.17385) already owns "web-scale 4D HOI data engine with automatic QA"; VITRA (ICRA'26, https://arxiv.org/abs/2510.21571) owns the pseudo-label scaling curve for hands; ForeHOI already shows feed-forward-replaces-optimization at ~100x; Liu et al. CVPR'21 (https://arxiv.org/abs/2106.05266) is the canonical HOI pseudo-labeling precedent. Position must be "first distillation of joint-optimization temporal coherence", with per-frame-pipeline labels as the decisive ablation.
- **Crowdedness: crowded** and converging from four directions.
- **Top risks.** (1) The necessity ablation *is* the paper: if smoothed per-frame pseudo-labels (or derivative losses on existing sequential GT — DexYCB/HOI4D GT is temporal, so the "no temporal signal" premise is false as stated) distill equally well, the contribution collapses to a loss recipe. (2) Sequential dependency on an unbuilt teacher (a paper premised on another unwritten paper). (3) QA gates validate image space, not 3D — the harness's own SAM-3D −21% aspect bias passes every gate; biases are systematic, confidence weighting fixes variance only. (4) Acceleration headline is gameable by over-smoothing; HOI4D derivative GT is noisy. (5) Realistic wild-footage yield (20-40%) pushes cost to 30-80k GPU-h.
- **Scores.** novelty 5.5, feasibility 4.5, crowd-inv 3, venue-fit 6, **overall 4.5**. **Verdict: maybe** — gate on (1) teacher proven smoother AND ≥ per-frame accuracy without GT depth on ≥20 clips; (2) 100-clip pilot with three label conditions (joint-optimized vs smoothed-per-frame vs existing-GT+derivative-losses) + student+SmoothNet baseline. Scale only on a decisive win.

### b5 — Method-agnostic GS temporal refinement layer (bind-then-refine) — **5.5/10, maybe (ranked #2)**

- **Idea/angle.** Plug-in test-time refiner: canonicalize ANY method's output via the existing scene contract (compare/scenes/*.npz), bind ~15-25k MANO-face-frame hand Gaussians + ~10-30k rigidly-bound object Gaussians, fit appearance briefly then **freeze it**, then re-optimize pose trajectories only (B-spline/DCT basis) against all-frame composited L1+D-SSIM + silhouette + optional depth + acceleration + camera-invariant grasp-relative smoothness + contact persistence + Geman-McClure trust region to the baseline. ~5-10 min/clip on one 4090. Evaluated as a **delta on all four baselines** plus a formalized temporal-stability benchmark. Key mechanism: one fixed-size canonical object must photometrically reproject in every frame, so 1/z size flicker becomes a depth gradient — supervision that evidence-free smoothing cannot access.
- **Novelty delta.** The exact slot is unoccupied: TOCH (ECCV'22, https://arxiv.org/abs/2205.07982), GeneOH Diffusion (ICLR'24, https://arxiv.org/abs/2402.14810), SmoothNet (ECCV'22, https://arxiv.org/abs/2112.13715) are evidence-free refiners that never consult pixels and cannot fix depth/scale; GS-CPR (ICLR'25, https://arxiv.org/abs/2408.11085) proves the frozen-GS test-time pose-refinement mechanism but for static cameras; 6DOPE-GS (ICCV'25) covers single rigid objects; BIGS/GHOST/DyTact are from-scratch per-scene reconstruction. The composition (canonicalize-any-method + freeze appearance + pose-only all-frame refinement + cross-method uniform-delta protocol) is new.
- **Crowdedness: moderate** — the slot is empty but all ingredients are popular; compressible to "SmoothNet-shape + GS-CPR-mechanism for HOI".
- **Top risks.** (1) Monocular scale-depth null space: uniform rescale + depth shift renders identically, so rigidity supervises only *relative* depth jitter — the "fixes what smoothing cannot" claim needs a metric anchor in the loss. (2) The 4/4-baseline claim likely breaks on HORT (−81% depth is far outside the photometric basin). (3) Appearance fit at wrong jittered poses bakes error in before the freeze. (4) Symmetric, mostly-occluded objects leave photometric terms uninformative exactly where stabilization is claimed. (5) Circular metrics unless GT-motion accel error and accuracy improve.
- **Scores.** novelty 5.5, feasibility 6, crowd-inv 4, venue-fit 6, **overall 5.5**. **Verdict: maybe** — 2-3 week pilot on 5-10 rigid HOI4D clips (RC + ForeHOI + do-as-i-do) must show non-circular accuracy gains beyond GeneOH/SmoothNet and a demonstrated depth/scale correction with mechanism ablated; pre-plan the HORT failure as an analyzed limitation.

### b6 — GS-based metric-gauge substrate feeding unchanged HOI pipelines — **5.5/10, maybe (RECOMMENDED)**

- **Idea/angle.** Attack the diagnosed root cause only. No hand/object Gaussians. A **dynamic-masked static-scene 3DGS bundle adjustment** (all frames jointly) recovers camera trajectory, ONE global metric scale, and per-frame affine depth-gauge corrections (a_t, b_t) on the MoGe-2/DA3 prior; the background-fitted gauge is **transferred to hand/object pixels** (valid iff the failures are per-frame *global* gauge errors — exactly what the diagnostics show: uniform 0.77x hand scale, z-only teleports, 2x scale swing); GS additionally renders **amodal support-surface depth** behind the dynamic masks. Inject through the interfaces the harness already proves out (render_and_compare sensor-depth path = 0% error under GT injection; do-as-i-do --gt-anchor + grasp-preserving common-delta; closed-form re-gauge for HORT/ForeHOI). Evaluate with the **oracle sandwich**: every method × {monocular, +substrate, +GT-depth}; headline = fraction of the oracle gap closed with (near-)unchanged methods, decomposing HOI jitter into gauge vs pose vs shape error.
- **Novelty delta.** Components exist separately — TRAM (ECCV'24, https://arxiv.org/abs/2403.17346) derives metric scale from masked background for *bodies*; DAS3R (https://arxiv.org/abs/2412.19584) does dynamic-masked static GS (not metric, no transfer); HaWoR does masked SLAM + metric depth for hands only; ViPE/MegaSaM (https://arxiv.org/abs/2412.04463) are commodity metric depth+pose engines — but **no work recovers the full substrate via static-scene GS-BA, transfers the gauge to dynamic HOI pixels, injects into four unchanged SOTA pipelines, or runs the oracle-controlled causal decomposition**. WHOLE (https://arxiv.org/abs/2602.22209) assumes metric-SLAMed Aria input and trains a new estimator. Novelty lives in the HOI-domain causal diagnosis + injection protocol + decomposition benchmark.
- **Crowdedness: moderate** — crowded neighborhood, empty niche (no analysis-style paper of this kind exists for HOI).
- **Top risks.** (1) **Make-or-break:** if ViPE/MegaSaM/Video-Depth-Anything fed through the same interfaces close a similar oracle-gap fraction, the GS-BA is dead weight and the paper demotes to analysis. (2) Affine gauge fitted on a narrow-depth-range tabletop background may be ill-conditioned and may not extrapolate to near-field hand/skin pixels (depth nets have region-dependent bias) — but this is **verifiable per-pixel on HOI4D GT depth in week one, before any GS code is written**. (3) Evidence base is n=1 kettle clip; oracle residuals (SAM-3D −21% shape, surviving HaWoR wobble) cap the ceiling. (4) "Unchanged pipelines" is only literally true for render_and_compare. (5) Eval matrix × do-as-i-do's 3 h/clip explodes compute.
- **Scores.** novelty 5.5, feasibility 7.5, crowd-inv 4.5, venue-fit 6, **overall 5.5**. **Verdict: maybe (strongest)** — run the two gating pilots; every outcome is informative (see below).

## Recommended direction: b6 — the metric-gauge substrate + oracle-sandwich causal decomposition

**Why this branch.** Three reasons, in order of weight:

1. **It attacks the failure the harness actually proved, with the mechanism the harness actually validated.** The controlled experiments are unambiguous: GT-depth injection makes the *unchanged* pipelines essentially exact (0% object depth/size error for render_and_compare); a better depth net changes nothing; filtering fixes only the high-frequency band. That is a measured statement that the per-frame metric gauge — not pose estimation, not contact modeling — dominates the error. b1-b3 all spend their machinery on pose/contact coupling and each carries a known-unsound mechanism (b1's dynamic-object depth triangulation does not exist in principle; b2/b3's grasp weld imports the HaWoR error this team already diagnosed and reverted). b6 is the only branch whose core mechanism is *already demonstrated* in-repo, just with GT depth standing in for the substrate.

2. **It is the most feasible and the most falsifiable.** Feasibility 7.5 — highest of all six. GS-BA is 10-40 min/clip vs hours for b1-b3; injection interfaces exist and are proven (`real_perception.py` sensor-depth path, `--gt-anchor`); and — uniquely — the load-bearing assumption (background-fitted affine gauge corrects hand/object-region depth) is **checkable per-pixel against HOI4D GT depth in the first week, before building anything**. No other branch offers a one-week kill switch.

3. **The niche is genuinely empty and it de-risks everything else.** Nobody has published an oracle-controlled causal decomposition of 4D-HOI temporal error into gauge vs pose vs shape components, and no substrate paper feeds unchanged HOI pipelines. Whatever the outcome, b6 produces the scaled harness (n=1 → n≈40 clips), the stability-metric protocol, and the quantitative answer to "how much of b1-b3's would-be gain is scale stabilization vs pose coupling" — which is precisely the ablation reviewers will demand from any sibling branch. If b6's method contribution gets commodity-matched, the substrate becomes infrastructure for b5, and the analysis folds into whichever sibling survives.

**Precise delta vs closest published work.**
- vs **TRAM** (ECCV'24): TRAM masks humans out of SfM and scales camera motion from the background for *body* mesh recovery with a retrained regressor; b6 recovers a per-frame affine *depth gauge* + one global scale via static-scene GS-BA, transfers it to dynamic hand/object pixels, and upgrades **four unchanged third-party HOI pipelines** — no retraining, plus amodal support-surface depth and grasp-preserving re-anchoring for the manipulated unknown object.
- vs **ViPE/MegaSaM/Video-Depth-Anything**: commodity engines output consistent metric depth+pose but nobody has shown what fraction of HOI reconstruction error they fix; b6's contribution is the causal decomposition and injection protocol, with GS-BA justified only if it beats them (joint camera+scale coupling, amodal support depth, per-pixel uncertainty are the candidate advantages) — this comparison is designed in, not dodged.
- vs **DAS3R**: dynamic-masked static GS exists, but not metric, with no gauge transfer to dynamic pixels and no downstream task.
- vs **WHOLE / AGILE / CHOIR**: all build *new* HOI estimators; b6 changes the input to existing ones and quantifies the causal structure — a complementary, unoccupied paper shape.

**Honest framing to adopt from the start** (pre-empting the pressure-test): the paper is a **diagnosis + substrate + decomposition benchmark**, not "unchanged pipelines" absolutism (only render_and_compare is literally unchanged; do-as-i-do gets an anchor flip, HORT/ForeHOI get output re-gauging — state this plainly). The headline number is "fraction of the GT-depth oracle gap closed from RGB alone."

## Practical pipeline

**Target venue & deadline-class.** CVPR 2027 (deadline ~Nov 2026; ~4.5 months) as a 3D-vision analysis + systems paper. Fallback: ICCV/3DV. CoRL only if a retargeting-to-robot downstream result is added via the do-as-i-do stack. Not ICLR (no learning contribution).

**Datasets/benchmarks.**
- **HOI4D** rigid categories (kettle, bottle, mug, toy car): scale the existing GT-depth harness from 1 kettle clip to **20-50 clips** with GT align_depth + object pose + MANO — this scale-up is itself a deliverable and must happen first regardless of branch.
- Second RGB-D HOI dataset for external validity: **DexYCB or H2O** (GT motion for non-circular acceleration metrics).
- **wild6** clips for qualitative in-the-wild results (MASt3R-SLAM/MegaSAM cameras).

**Baselines / comparison conditions.**
- The 4 pipelines raw (render_and_compare, do-as-i-do, ForeHOI, HORT).
- Each + **oracle-tuned output filtering** (OneEuro, median+MA, spline, Kalman) — the decisive cheap-fix control.
- Each + **commodity substrates**: ViPE, MegaSaM, Video-Depth-Anything, COLMAP+MVS, per-frame depth + temporal filtering — fed through the *identical* injection interfaces (the make-or-break ablation).
- Each + **GS-BA substrate** (the method).
- Each + **GT align_depth** (the oracle ceiling).

**Method components & how to build each.**
1. *Priors:* reuse SAM2/SAM3 point-prompt masks (protocol already validated — text prompts grab wrong instances), MoGe-2/DA3-metric depth, GeoCalib gravity. All wired in-repo.
2. *Static-scene GS-BA:* gsplat-based; optimize {background Gaussians, per-frame T_t ∈ SE(3), global scale s, per-frame (a_t, b_t)} under mask-gated L1+D-SSIM on background pixels + λ|D_GS,t − (a_t·D_mono,t + b_t)| on co-visible static pixels + gravity alignment + shrinkage of (a_t,b_t)→(1,0) + camera smoothness. Static-camera clips degrade gracefully to multi-frame depth consensus. Optional: object-at-rest support-plane contact to pin s.
3. *Gauge transfer:* apply D~_t to all pixels; render amodal support depth + opacity/residual reliability maps.
4. *Injection:* 16-bit metric depth + K through `real_perception.py`'s sensor-depth path (render_and_compare); `--gt-anchor` pointmap + grasp-preserving common-delta (do-as-i-do); closed-form per-frame translation + one global scale aligning predicted points to D~_t inside their own masks (HORT/ForeHOI).
5. *Metrology:* formalize the repo's diagnostics into a stability suite (below).

**Key experiments + ablations (in execution order — the first two are gates).**
1. **Gate 1 (week 1, before any GS code):** on ≥10 HOI4D clips, fit (a_t, b_t) on background pixels against the mono-depth prior and verify per-pixel on GT align_depth that the correction reduces *hand/object-region* depth error. If affine transfer fails → drop the branch (cost: ~2 weeks).
2. **Gate 2 (weeks 2-3):** ViPE/MegaSaM/VDA through the same interfaces on the same clips. If commodity matches GS-BA → keep the substrate as infrastructure, pivot the paper to the decomposition/benchmark and reinforce b5.
3. **Oracle sandwich** (headline table): 4 methods × {mono, +substrate, +GT} × 20-50 clips; report fraction of oracle gap closed per metric, plus the gauge/pose/shape error decomposition (oracle residuals — SAM-3D −21% shape, HaWoR wobble — quantify the non-gauge components).
4. **Cheap-fix control:** oracle-tuned filters must NOT match the substrate on accuracy (they will match on some stability metrics — say so).
5. **Component ablations:** affine vs scale-only vs shift-only gauge; with/without amodal support depth; with/without gravity; static-camera subset; support-plane scale pinning on/off; anchor-flip on/off for do-as-i-do.
6. **Robustness reporting:** per-clip success rates, mask-leakage cases (the SAM3 wrong-kettle failure is already documented — feature it), frames where hands+object dominate.
7. *Compute pruning:* run do-as-i-do (~3 h/clip) on a 10-clip subset only, disclosed; full matrix on the three cheaper pipelines.

**Evaluation metrics.**
- *Accuracy:* object size error, absolute depth error, center error, ADD-S/Chamfer, hand MPJPE/MRRPE.
- *Stability:* apparent-size flicker and low-frequency swing (the two-band decomposition — keep this analysis, it is the paper's sharpest tool), depth wiggle ratio (z-path/net-displacement), acceleration jitter, hand-object depth-anchor correlation, grasp consistency. Always paired with accuracy to defuse the "smoothing wins stability for free" attack.

**Milestone timeline (to ~Nov 2026).**
- **Weeks 1-3:** Gates 1 & 2 (kill/pivot decision). In parallel: scale harness to 20 HOI4D clips.
- **Weeks 4-7:** GS-BA implementation + gauge transfer + injection into render_and_compare and HORT/ForeHOI; first oracle-sandwich slice on 10 clips.
- **Weeks 8-11:** do-as-i-do anchor flip + grasp-preserving delta; harness to 40-50 clips; DexYCB/H2O port; commodity-substrate full comparison.
- **Weeks 12-15:** full matrix, ablations, per-clip success rates, wild6 qualitative.
- **Weeks 16-18:** writing, figures, the causal-decomposition narrative; buffer for one rebuttal-grade extra experiment (e.g., substrate feeding one newest external SOTA method to counter "why these baselines").
